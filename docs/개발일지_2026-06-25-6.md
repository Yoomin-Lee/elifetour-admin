```sql
ALTER TABLE voyage_flights
  ADD COLUMN IF NOT EXISTS seats_group    INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS seats_indivi   INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS seats_business INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_base      INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_fuel      INTEGER NOT NULL DEFAULT 0,
```

```sql
ALTER TABLE flights
  ADD COLUMN IF NOT EXISTS seats_group    INTEGER NOT NULL DEFAULT 0,
  -- (동일 6개 컬럼)
```

> **주의**: 두 테이블은 별개. `voyage_flights`는 FlightsTab(DST 반영 TIMESTAMPTZ 기반), `flights`는 FlightsEditor/FlightsCard(단순 날짜/시각 문자열 기반)로 각각 독립적으로 운용.

### 2. FlightsTab — 꺽새 확장 패널 (`FlightsTab.tsx`, `voyageFlights.ts`)

**개요**  
항공 탭 마스터 테이블의 각 행에 꺽새(▶) 버튼 추가. 클릭 시 `SeatsPanel` 서브 컴포넌트가 펼쳐지며 두 수식을 표시/편집.

**수식 구조**
```
그룹 N석 + 인디비 N석 + 비즈니스 N석 = 총 N석
운임 N원 + 유류할증료 N원 + 발권피 N원 = N원 (KRW 천단위 콤마, 소수점 없음)
```

**SeatsPanel 동작**
- 조회 모드: 수식 결과 표시
- 편집 모드(편집 버튼): 6개 숫자 입력 → 실시간 합산 → 저장 시 `updateVoyageFlight` 호출
- 저장 후 `['all-voyage-flights']` 쿼리 무효화로 메인 테이블도 즉시 갱신

**메인 행 `항공요금` 컬럼 업데이트**  
분류값(fare_base + fare_fuel + fare_tax)이 입력된 경우 합산 KRW로 표시, 없으면 기존 `flight_fare`로 폴백.

**타입 변경** (`VoyageFlight`, `VoyageFlightInput`)  
6개 필드 추가. `updateVoyageFlight`에서 patch 처리.

### 3. FlightsEditor 재설계 (`FlightsEditor.tsx`, `voyage.ts`)

새행사 등록 폼의 항공 섹션을 완전히 재설계. 정보 우선순위 역전.

**Before**
```
[편명] [출발지] [도착지] [소요시간]
[출발일] [출발시간] [도착일] [도착시간]
```

**After**
```
[그룹(석)] + [인디비(석)] + [비즈니스(석)] = 총 좌석 (실시간 합산)
──────────────────────────────────────────────────────────
[운임(원)] + [유류할증료(원)] + [발권피(원)] = 항공료 (KRW)
──────────────────────────────────────────────────────────
▶ 편명 · 날짜 · 시각 상세  ← 접이식, 기본 접힘
   [편명] [출발지] [도착지] [소요시간(자동계산)]
   [출발일] [출발시간] [도착일] [도착시간]
```

**실시간 합산 구현**  
`useWatch`로 6개 필드를 한 번에 구독, `Number(v) || 0` 변환 후 합산.

```ts
const [sg, si, sb, fb, ff, ft] = useWatch({
  control,
  name: [
    `flights.${index}.seats_group`,
    // ... 5개 더
  ],
}).map(v => Number(v) || 0)
const totalSeats = sg + si + sb
const totalFare  = fb + ff + ft
```

**스키마 변경** (`flightSchema`)

```ts
seats_group:    z.coerce.number().min(0).default(0),
seats_indivi:   z.coerce.number().min(0).default(0),
seats_business: z.coerce.number().min(0).default(0),
fare_base:      z.coerce.number().min(0).default(0),
fare_fuel:      z.coerce.number().min(0).default(0),
fare_tax:       z.coerce.number().min(0).default(0),
```

VoyageNew의 submit 핸들러(`flights.map(f => ({ ...f, voyage_id: id, ... }))`)가 폼 필드를 통째로 DB에 전달하므로 별도 수정 불필요.

### 4. FlightsCard 재설계 (`FlightsCard.tsx`, `database.ts`)

항차 상세 화면의 항공 카드를 FlightsEditor와 동일한 구조로 재설계.

**조회 모드 변경**  
기존 테이블 뷰 → 항공편별 카드 뷰로 전환.

```
┌─────────────────────────────────────────────┐
│ 1편                                          │
│ 그룹 N석 + 인디비 N석 + 비즈니스 N석 = 총 N석 │
│ 운임 N원 + 유류할증료 N원 + 발권피 N원 = N원  │
│ KE907 · 인천(ICN) → 바르셀로나(BCN) · MM/DD  │  ← compact 하위
└─────────────────────────────────────────────┘
```

**편집 모드 변경**  
`FlightDraftRow` 재설계 — 좌석/항공료 입력이 메인, 편명·날짜·시각은 접이식 하위.

**`DraftFlight` 타입 확장**  
6개 필드 추가 (string 형태로 저장, `toInput()`에서 `Number()` 변환).

**`Flight` 인터페이스 확장** (`database.ts`)  
`seats_group`, `seats_indivi`, `seats_business`, `fare_base`, `fare_fuel`, `fare_tax` 추가.  
`FlightInput = Omit<Flight, 'id' | 'voyage_id' | 'created_at'>`이 자동으로 이를 포함.

## 기술 포인트

### 두 항공 테이블의 구분
- `voyage_flights`: FlightsTab 전용. TIMESTAMPTZ 기반, DST 반영 현지 시각 변환 (`toZonedTime`). PNR, 항공사 코드(IATA) 별도 관리.
- `flights`: FlightsEditor/FlightsCard 전용. 날짜·시각을 문자열로 저장. Zod 스키마 기반 폼 데이터가 그대로 삽입됨.

### useWatch 배열 구독
단일 `useWatch` 호출로 6개 필드를 배열로 구독하면 리렌더링 횟수를 최소화할 수 있음.  
각 필드에 `useWatch`를 따로 쓰면 변경될 때마다 6번 렌더가 발생하지만, 배열 구독은 한 번으로 처리.

### `toInput()` 타입 안전성
`FlightInput = Omit<Flight, 'id' | 'voyage_id' | 'created_at'>`이므로 `Flight`에 필드를 추가하면 TypeScript가 `toInput()`의 반환값에도 해당 필드를 요구함. 이를 통해 새 컬럼 추가 시 저장 누락을 컴파일 타임에 감지 가능.

### formatKrw 패턴
`n.toLocaleString('ko-KR') + '원'` — 소수점 없이 천단위 콤마 자동 적용. 0은 `'—'`로 표시.
