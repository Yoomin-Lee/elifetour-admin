## 결정 사항

### 기술 스택

| 항목 | 결정 | 이유 |
|------|------|------|
| 프레임워크 | Vite + React 19 유지 | GitHub Pages 정적 배포와 호환, 마이그레이션 비용 없음 |
| UI 라이브러리 | Shadcn UI 추가 (신규 페이지 전용) | 기존 스타일 영향 없이 모던 컴포넌트 사용 가능 |
| 언어 | 기존 JS 유지 + 신규 파일 TypeScript | 기존 코드 안전, 신규 기능은 타입 안전성 확보 |
| 데이터 페칭 | TanStack Query | 서버 상태 캐싱, 낙관적 업데이트, 동시 편집 처리 |
| 폼/검증 | React Hook Form + Zod | 클라이언트·서버 공용 스키마 재사용 |
| 배포 | GitHub Pages 유지 | 변경 없음 |

### 아키텍처

- 기존 앱에 **페이지 추가** 방식 (전체 리빌드 없음)
- 기존 `.jsx` 파일 **절대 수정 금지**
- Shadcn UI는 신규 페이지에만 적용
- Supabase 타입 자동 생성(`gen types`) 활용

## 신규 요구사항 (`docs/requirements.md`)

### 데이터 모델

| 테이블 | 설명 |
|--------|------|
| `voyages` | 행사/항차 마스터 (개요, 선사, 날짜, 캐빈 현황 등) |
| `flights` | 항공 정보 (voyage당 N개) |
| `itinerary_days` | 기항지 일정 (날짜별, 해상일 포함) |
| `cancellation_policies` | 취소료 구간 (D-day 기준, fee 구조화) |
| `history_logs` | 수동 메모 히스토리 |
| `audit_logs` | DB trigger 자동 감사 로그 |

### 화면 구성

- `/voyages/search`: 상단 행사 선택 Combobox → 개요·항공·기항지·취소료·히스토리 5개 섹션
- `/voyages`: 전체 행사 목록 (필터·정렬)
- `/voyages/new`: 새 행사 등록 폼
- URL `?voyage={id}` 쿼리로 링크 공유 가능

### 핵심 UX 포인트

- 취소료 테이블: 오늘 날짜가 속한 구간 행 하이라이트
- 히스토리: 인라인 새 메모 추가
- Realtime: 다른 직원 수정 시 즉시 반영 + toast 알림
- 데스크탑 2단 / 모바일 1단 레이아웃
