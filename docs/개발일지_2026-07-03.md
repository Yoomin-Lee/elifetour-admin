### 2. 보유 현황 — n인실 표시·편집 확장

#### 크루즈 컬럼에 n인실별·등급별 잔여캐빈 뱃지 (`InventoryTab.tsx`)

상세를 펼치지 않아도 한눈에 보이도록, 크루즈 컬럼에 등급별 뱃지 앞에 n인실별 집계 뱃지를 추가.

```ts
function groupByOccupancy(grades: CabinGrade[]): { occupancy: number; total: number; remaining: number }[] {
  const map = new Map<number, { total: number; reserved: number }>()
  grades.forEach(g => {
    if (g.occupancy == null) return
    const cur = map.get(g.occupancy) ?? { total: 0, reserved: 0 }
    cur.total += g.total
    cur.reserved += g.reserved
    map.set(g.occupancy, cur)
  })
  return Array.from(map.entries())
    .sort(([a], [b]) => a - b)
    .map(([occupancy, { total, reserved }]) => ({ occupancy, total, remaining: total - reserved }))
}
```

#### 펼치기(꺾새) 상세의 크루즈 선실 표에도 n인실 컬럼 추가

### 3. 드롭다운 공통 버그 3건 수정 (`FieldSelect` 및 파생 컴포넌트)

#### ① 옵션 텍스트 줄바꿈

체크 표시가 있는 선택된 옵션에서, 좁은 트리거 너비에 맞춰 라벨 텍스트가 줄바꿈되던 문제. `whitespace-nowrap` + `w-max`로 콘텐츠 기준 너비를 확보하도록 수정.

#### ② 표 자체 스크롤바로 인한 드롭다운 잘림

`overflow-x-auto`만 지정하고 `overflow-y`를 지정하지 않으면 브라우저가 `overflow-y`도 강제로 `auto`로 처리해, 크루즈 선실 표 컨테이너가 드롭다운을 세로로 클리핑하는 문제. 해당 wrapper의 `overflow-x-auto` 제거(가로 스크롤은 상위 테이블 컨테이너가 이미 처리).

#### ③ 드롭다운 열린 채로 취소/저장 버튼 클릭 시 클릭이 씹히는 버그

**원인**: 바깥 클릭 감지를 전체 화면을 덮는 투명 오버레이(`<div className="fixed inset-0 z-10" onClick={...} />`)로 구현해서, 드롭다운이 열린 상태에서 다른 버튼(취소 등)을 클릭하면 그 클릭을 오버레이가 가로채 버튼까지 전달되지 않았음. 편집 모드가 계속 유지되며 수정값이 화면에 남아있는 것처럼 보였던 원인.

**수정**: 공용 훅 `src/hooks/useClickOutside.ts` 신설, `document`의 `pointerdown` 이벤트로 바깥 클릭을 감지하되 오버레이로 클릭을 막지 않도록 변경.

```ts
export function useClickOutside(ref: RefObject<HTMLElement | null>, active: boolean, onOutside: () => void) {
  useEffect(() => {
    if (!active) return
    function handlePointerDown(e: PointerEvent) {
      if (ref.current && !ref.current.contains(e.target as Node)) onOutside()
    }
    document.addEventListener('pointerdown', handlePointerDown)
    return () => document.removeEventListener('pointerdown', handlePointerDown)
  }, [active, ref, onOutside])
}
```

같은 오버레이 패턴이 아래 6곳에도 동일하게 있었고, 전부 `useClickOutside`로 교체:

- `ui/year-select.tsx`
- `tabs/ProductTab.tsx` (상태 필터 드롭다운)
- `voyages/CancellationCard.tsx`, `voyages/CancellationEditor.tsx` (취소료 프리셋 불러오기)
- `voyages/ItineraryCard.tsx`, `voyages/ItineraryEditor.tsx` (일정 루트 불러오기)

실제 모달(사용자 관리, 협력업체 등록, 삭제 확인, 프리셋 관리 모달 등)의 배경 오버레이는 클릭 차단이 의도된 동작이라 그대로 유지.

### 5. 항차 상세 — 다른 메뉴 봤다 돌아와도 마지막 조회 항차 유지

#### 배경

항차 상세(`VoyageSearch.tsx`)의 현재 선택 항차는 URL의 `voyage` 쿼리 파라미터로만 관리되는데, 탭을 전환하거나 다른 메뉴로 이동하면 `VoyageMasterInner`의 `switchTab`이 해당 파라미터를 삭제해서, 다시 항차 상세로 돌아오면 선택이 초기화되는 문제.

#### 수정 (`src/lib/lastVoyage.ts` 신설 + `VoyageSearch.tsx`)

모듈 스코프 변수로 마지막 조회 항차 id를 기억(새로고침 시 모듈이 재로딩되므로 자연히 초기화됨):

```ts
let lastVoyageId: string | null = null
export function getLastVoyageId(): string | null { return lastVoyageId }
export function setLastVoyageId(id: string | null) { lastVoyageId = id }
```

`VoyageSearchInner`에 마운트 시 1회 복원 + 조회 시마다 기억하는 effect 2개 추가:

```ts
// 마운트 시 1회만 복원 — 조회 중 필터 변경/삭제로 인한 명시적 선택 해제는 덮어쓰지 않음
useEffect(() => {
  if (!voyageId) {
    const remembered = getLastVoyageId()
    if (remembered) setSearchParams(prev => { ...; next.set('voyage', remembered); return next }, { replace: true })
  }
}, [])

// 조회한 항차는 계속 최신 상태로 기억
useEffect(() => { if (voyageId) setLastVoyageId(voyageId) }, [voyageId])
```

삭제 시에는 `setLastVoyageId(null)`도 함께 호출해, 삭제한 항차가 다음 방문 때 다시 복원되지 않도록 처리.

### 6. 결제 스케줄 — 메모 줄바꿈 입력 + 카드 자동 높이 조절

#### 배경

메모 필드가 단일 라인 `Input`이라 Enter로 줄바꿈이 안 되고, 긴 메모는 잘려 보였음. 스크롤 없이 카드 자체가 내용 길이에 맞춰 늘어나도록 요청.

#### 신규 컴포넌트 (`src/components/ui/auto-textarea.tsx`)

`scrollHeight` 기준으로 매 입력마다 높이를 재계산하는 `AutoTextarea`:

```tsx
function resize(el: HTMLTextAreaElement) {
  el.style.height = 'auto'
  el.style.height = `${el.scrollHeight}px`
}

useLayoutEffect(() => { if (innerRef.current) resize(innerRef.current) }, [value])

<textarea
  rows={1}
  onInput={e => { resize(e.currentTarget); onInput?.(e) }}
  className="... resize-none overflow-hidden ..."
/>
```

`resize-none overflow-hidden`으로 자체 스크롤·수동 리사이즈를 막고, 부모 카드는 `min-h-[80px]`만 있고 고정 높이가 없어 텍스트영역이 늘어나면 카드도 자연히 함께 늘어남.

#### 적용 (`PaymentTab.tsx`)

- 편집 모드: 메모 `Input` → `AutoTextarea` 교체
- 보기 모드: 메모 `<p className="truncate">` → `<p className="whitespace-pre-wrap break-words">` — 줄바꿈이 그대로 보이도록 truncate 제거

### 9. 보유 현황 항공 좌석 — 항차 상세 데이터와 항상 동기화

#### 배경

`voyage_flights`(보유 현황 항공 좌석)는 항차 생성 시점에 `flights`(항차 상세) 테이블에서 딱 한 번만 미러링되고, 이후 항차 상세에서 편명·구간·좌석·운임을 수정해도 보유 현황 쪽엔 반영되지 않던 문제.

#### 수정

- **`voyage_flights.source_flight_id`** 링크 컬럼 추가(`20260703000001_voyage_flights_source_link.sql`) — 어느 `flights` 행에서 미러링됐는지 추적.
- **`resyncVoyageFlights(voyageId)`** (`voyages.ts`) — 기존 `voyage_flights` 행을 전부 지우고 `flights` 테이블 현재 상태 기준으로 재생성. 항차 생성 시점 미러링도 이 함수로 통일.
- 보유 현황 > 항공 좌석에 **"항차 상세에서 불러오기"** 버튼 추가 — 수동으로도 재동기화 가능.
- **`FlightsCard.tsx`에서 항공편 저장 시 자동으로 `resyncVoyageFlights` 호출** — 항차 상세를 저장할 때마다 보유 현황이 자동으로 최신 상태를 유지. 항차 상세/새행사등록의 항공 편집 UI 자체는 변경하지 않음.
- 보유 현황에서 좌석/운임을 수정하면, 연결된 `flights` 행이 있을 경우 **`updateFlightSeatsAndFare`로 그 행에도 반영한 뒤** `resyncVoyageFlights`를 호출 — 그래야 항차 상세 저장 시 자동 동기화가 보유 현황에서 한 수정을 덮어쓰지 않는다. 링크가 없는(마이그레이션 이전) 구버전 행은 기존처럼 `voyage_flights`에 직접 반영.

#### 시행착오: 행 추가 기능

동일 편명이라도 좌석 등급별로 운임이 다를 수 있어, 보유 현황에 편명·구간·일시를 직접 입력하는 "행 추가" 기능과 `flights` 테이블에 새 행을 생성하는 로직을 한 차례 구현했으나, 실무자 피드백으로 철회. 좌석 개수만 보이는 기존 방식을 유지하되, 위의 동기화 수정(`source_flight_id` 링크 + 좌석/운임 반영)은 그대로 남겨둠 — 이 부분은 행 추가와 무관하게 데이터 정합성을 위해 필요.

### 10. 항공편 — 같은 구간(편명·일시)으로 메인(좌석·운임)만 추가

#### 배경

동일 편명·구간·일시인데 좌석 등급에 따라 운임이 달라지는 경우가 있음. 기존 "행 추가"는 매번 편명·출발지·도착지·날짜·시각을 처음부터 다시 입력해야 했음.

#### 1차: 구간 복제 버튼

`FlightsCard.tsx`(항차 상세)·`FlightsEditor.tsx`(새행사등록) 각 항공편 카드의 "편명·날짜·시각 상세" 영역에 **"같은 구간으로 좌석 수 및 요금 추가"** 버튼을 추가. 클릭하면 현재 카드의 구간(segments) 정보를 그대로 복제한 새 카드가 생성되고, 좌석·운임만 새로 입력하면 됨.

```ts
// FlightsCard.tsx
function duplicateRow(source: DraftFlight) {
  setDraft(d => [...d, { ...EMPTY, _key: `new-${Date.now()}`, segments: source.segments.map(s => ({ ...s })) }])
}
```

#### 2차: 메인 여러 개가 구간 1개를 공유하는 카드로 재구성

실무자 피드백: 복제된 카드가 완전히 새로운 메인+서브 카드로 아래에 따로 생기는 게 아니라, **메인-메인-서브** 순서로 하나의 카드에 끼워져 보이길 원함. 두 파일 모두 렌더링 구조를 재작업:

- **`FlightsCard.tsx`**: `DraftFlight`에 `_groupKey` 추가. 구간 내용이 같으면 로드 시점에 자동으로 같은 그룹으로 묶이고(`segmentsKey(segments) || f.id`), 복제 시엔 원본과 같은 `_groupKey`를 부여하며 원본 바로 뒤에 삽입(`d.slice(0, idx+1)`+새 행+`d.slice(idx+1)`)해 배열상 인접하도록 함. 인접한 같은 `_groupKey` 항목을 `groups: DraftFlight[][]`로 묶어 `FlightGroupCard`(메인 여러 개 + 구간 섹션 1개 공유) 단위로 렌더링. 구간 수정은 `updGroupSegments`로 그룹 내 모든 메인에 동일하게 반영.
- **`FlightsEditor.tsx`**: react-hook-form 기반이라 `_groupKey` 대신 매 렌더마다 `segmentsKey`로 인접 항목의 구간 값을 비교해 그룹을 계산(`useWatch({ name: 'flights' })`). 복제는 `append` 대신 `insert(afterIndex + 1, ...)`로 그룹 뒤에 삽입. `FlightGroupBlock`은 그룹의 첫 메인(`leadIndex`) 기준으로 구간을 편집하고, `useEffect`로 변경 내용을 그룹 내 다른 메인들의 `segments` 필드에 `setValue`로 동기화.

```tsx
// FlightGroupCard(FlightsCard.tsx) 구조
<div className="rounded-lg border ...">        {/* 그룹 카드 */}
  {rows.map((r, ri) => <MainFareBlock ... />)}  {/* 메인 N개 */}
  <button onClick={onAddMain}>같은 구간으로 좌석 수 및 요금 추가</button>
  <div>{/* 구간 상세, 그룹 공유 */}</div>
</div>
```

레이블은 처음엔 "같은 구간으로 메인 추가"였다가 "같은 구간으로 좌석 수 및 요금 추가"로 다시 변경.

데이터 모델은 변경 없음 — 그룹의 각 메인은 여전히 독립된 `flights` 행이라, 보유 현황 동기화 시 자동으로 각각 별도 좌석 행으로 표시된다.

### 11. 보유 현황 — 크루즈·항공 뱃지 및 컬럼 레이아웃 다듬기

여러 차례 실무자 피드백을 반영해 크루즈/항공/호텔 컬럼을 조정:

1. 크루즈 뱃지에서 등급 뱃지 제거, n인실 뱃지만 남김.
2. n인실 뱃지를 `flex-nowrap` + `overflow-x-auto`로 줄바꿈 없이 한 줄 표시(넘치면 네이비 스크롤바).
3. 호텔명이 잘리는 문제 발견 → 크루즈·항공 컬럼을 좁히고 호텔 컬럼에 공간 확보, `truncate` 제거로 긴 이름은 줄바꿈되어 전체 표시. 항공 편명 뱃지는 한 줄 스크롤 대신 다시 자연스러운 줄바꿈으로 되돌림.
4. 호텔 컬럼이 이번엔 반대로 너무 넓어져 보유캐빈과 간격이 벌어짐 → 호텔 컬럼에 고정 너비(`w-36`)를 다시 지정해 간격 조정.
5. 항공 편명 뱃지 레이아웃 규칙 추가: 2개 이하면 한 줄, 3개 이상이면 절반씩 나눠 출발편/도착편처럼 두 줄로 표시.

```tsx
const half = Math.ceil(flights.length / 2)
const rows = flights.length <= 2 ? [flights] : [flights.slice(0, half), flights.slice(half)]
```

보유현황 > 꺾새 > 편집 > 호텔 객실의 투숙일 입력도 네이티브 `<input type="date">`에서 프로젝트 공용 `DatePicker`(캘린더 드롭다운)로 교체해 다른 화면과 UI 통일. 해당 표 wrapper의 `overflow-x-auto`도 제거해 팝오버가 잘리지 않도록 함(크루즈 선실 표에서 있었던 것과 동일한 클리핑 문제를 미리 방지).
