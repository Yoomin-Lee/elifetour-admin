## 변경 사항

### 1. 항공편 다중 구간 지원 (`fe1b885`)

#### 배경
기존 FlightsEditor / FlightsCard는 항공편 하나에 편명·날짜·시각 정보를 단 하나만 입력할 수 있었음. 경유편이나 연결편을 표현하려면 메인 항공편을 여러 개 추가해야 하는 비효율이 있었음.

#### DB 마이그레이션 (`20260625200002_flights_segments.sql`)

```sql
ALTER TABLE flights
  ADD COLUMN IF NOT EXISTS segments JSONB NOT NULL DEFAULT '[]';
```

`flights` 테이블에 구간 배열을 JSONB로 저장. 기존 레코드는 `DEFAULT '[]'`로 마이그레이션 없이 호환.

#### `src/lib/schemas/voyage.ts`

`segmentSchema` 추가 — 편명·출발지·도착지·날짜·시각·소요시간 8개 필드.

```ts
export const segmentSchema = z.object({
  flight_no:      z.string().optional(),
  origin:         z.string().optional(),
  destination:    z.string().optional(),
  departure_date: z.string().optional(),
  departure_time: z.string().optional(),
  arrival_date:   z.string().optional(),
  arrival_time:   z.string().optional(),
  duration:       z.string().optional(),
})
```

`flightSchema`에 `segments: z.array(segmentSchema).default([])` 추가.

#### `src/types/database.ts`

`FlightSegment` 타입 추가, `Flight` 인터페이스에 `segments: FlightSegment[]` 추가.

#### FlightsEditor 재설계 (`src/components/voyages/FlightsEditor.tsx`)

**구조**
```
항공편 카드 (메인)
├── 그룹 + 인디비 + 비즈니스 = 총 좌석     ← 메인 수식
├── 운임 + 유류할증료 + 발권피 = 항공료    ← 메인 수식
└── ▶ 편명 · 날짜 · 시각 상세              ← 꺽새 클릭 시 펼침
    ├── [1구간] 편명 / 출발지 / 도착지 / 소요시간 / 날짜·시각
    ├── [2구간] ...
    └── [+ 구간 추가]                        ← 무제한 추가
```

**구현 포인트**
- `SegmentRow` 컴포넌트: `useFieldArray({ name: \`flights.${index}.segments\` })`로 nested 배열 관리
- 구간 수 뱃지: `segments.length > 0`이면 꺽새 옆에 `N구간` 뱃지 표시
- 좌석 수 입력 placeholder: `'0'` → `'좌석 수'` 로 변경

#### FlightsCard 재설계 (`src/components/voyages/FlightsCard.tsx`)

**SegmentDraft 타입 신설**

```ts
type SegmentDraft = {
  flight_no: string; origin: string; destination: string
  departure_date: string; departure_time: string
  arrival_date: string; arrival_time: string; duration: string
}
```

**DraftFlight 리팩터링**
- flat 필드(flight_no, origin 등) 제거 → `segments: SegmentDraft[]`로 통합

**레거시 마이그레이션 (`toDraft`)**
DB의 `segments` 배열이 비어있고 flat 필드에 데이터가 있는 기존 레코드를 읽을 때, 자동으로 첫 구간으로 마이그레이션.

```ts
if (segments.length === 0 && (f.flight_no || f.origin || ...)) {
  segments = [{ flight_no: f.flight_no ?? '', ... }]
}
```

**`toInput()` 업데이트**
- 첫 구간을 flat 컬럼(flight_no, origin 등)에도 미러링 → 하위 호환 유지
- `segments` 배열을 JSONB로 저장

**편집 모드 (`FlightDraftRow`)**
- `onUpdate` 시그니처를 `(updater: (prev: DraftFlight) => DraftFlight) => void`로 변경 — nested 구조 업데이트를 함수형으로 처리
- `SegmentDraftRow` 컴포넌트: 구간별 독립 편집 + `useFlightCalc`로 소요시간 자동계산

**조회 모드**
- `segments` 배열이 있으면 구간별 표시
- 없으면 flat 필드 폴백 (레거시 데이터 대응)

## 기술 포인트

### Nested useFieldArray
React Hook Form의 `useFieldArray`는 중첩 배열도 지원. `name: \`flights.${index}.segments\``처럼 점(.) 표기법으로 중첩 경로를 지정하면 됨. 단, TypeScript 타입 추론이 깊은 중첩에서 약해지므로 `as any` 캐스팅이 필요한 경우가 있음.

### 함수형 updater 패턴
편집 모드에서 nested 상태 업데이트는 `setState(updater)` 패턴이 깔끔함.

```ts
// 구간 업데이트
onUpdate(prev => ({
  ...prev,
  segments: prev.segments.map((s, i) =>
    i === segIdx ? { ...s, [field]: value } : s
  ),
}))
```

setter를 직접 전달하면 콜백마다 클로저가 달라지는 stale closure 문제를 방지할 수 있음.

### JSONB 저장 시 flat 컬럼 미러링
기존 플랫 컬럼(`flight_no`, `origin` 등)을 즉시 제거하지 않고, `toInput()`에서 첫 구간을 플랫 컬럼에도 함께 저장. 이렇게 하면 구버전 코드나 직접 쿼리 시에도 첫 구간 정보를 조회할 수 있어 무중단 마이그레이션이 가능함.
