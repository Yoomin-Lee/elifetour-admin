### 1. `partners` 테이블 미생성 문제 확인 및 수정

memory에 "`supabase/migrations/20260616100000_partners.sql` 미실행"으로 남아있던 항목을 확인하는 작업. Supabase REST API(`/rest/v1/partners`)를 anon key로 직접 조회해본 결과 `PGRST205 Could not find the table 'public.partners'` 404 응답 — 실제 프로덕션 DB에 `partners` 테이블이 생성되어 있지 않은 상태였음. 반면 앱 코드(`src/pages/Partners.tsx`, `src/lib/queries/partners.ts`)는 이미 이 테이블을 사용하고 있어, 배포된 사이트의 협력업체 관리 화면이 정상 작동하지 않고 있었던 것으로 확인.

CLI(`npx supabase migration list`)로 상태를 확인하려 했으나 `.env.local`의 `SUPABASE_ACCESS_TOKEN`이 401 Unauthorized를 반환 — 토큰이 만료/폐기된 상태로 CLI를 통한 마이그레이션 적용이 불가능했음.

대안으로 Supabase 대시보드 SQL Editor에서 수동 실행하는 방법을 선택. 다음 두 마이그레이션을 순서대로 합쳐서 실행:
- `20260616100000_partners.sql` — `partners` 테이블 생성 + 기본 RLS 정책(관리자·직원 모두 등록/수정 가능)
- `20260626000000_staff_readonly.sql` 중 `partners` 관련 블록 — 이후 정책을 "관리자만 등록/수정 가능"으로 재조정하는 부분

두 파일 모두 `IF EXISTS`/`IF NOT EXISTS` 가드가 있어 반복 실행해도 안전하게 설계되어 있었음. 실행 후 REST API로 재조회해 `partners` 테이블이 정상적으로 존재하고(`[] / HTTP 200`) 빈 결과를 반환하는 것을 확인.

**확인된 사실 (memory 반영):**
- Phase 1 테이블(`eli_trips`, `eli_passengers`, `eli_profiles`)만 `eli_` 접두사를 쓰고, Phase 2 이후 테이블(`voyages`, `voyage_flights`, `hotels`, `partners`, `flights`, `feedback_logs` 등)은 접두사 없이 생성되어 있음.
- Supabase CLI 액세스 토큰이 만료되어 있어, 당분간 새 마이그레이션은 대시보드 SQL Editor에서 수동 실행이 필요함.
