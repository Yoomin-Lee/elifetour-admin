### 1. 행사 삭제 기능 추가 (`src/pages/VoyageSearch.tsx`, `src/lib/queries/voyages.ts`)

항차 조회 탭에서 선택된 행사를 삭제하는 기능 구현.

**`deleteVoyage` 함수** (`src/lib/queries/voyages.ts`)
```ts
export async function deleteVoyage(id: string): Promise<void> {
  const { error } = await sb().from('voyages').delete().eq('id', id)
  if (error) throw error
}
```
`voyages` 레코드만 삭제하면 FK `ON DELETE CASCADE`로 하위 테이블 자동 삭제:
- flights, itinerary_days, cancellation_policies, history_logs, hotels, cabin_grades, payment_schedules → 전부 CASCADE
- passengers → `ON DELETE SET NULL` (여행자 데이터는 보존)

**UI (`VoyageSearch.tsx`)**

- `window.confirm` 확인 다이얼로그
- 성공 시: 토스트 `'삭제되었습니다'` + `invalidateQueries(['voyages'])` + URL에서 voyage 파라미터 제거

### 3. 새 행사 등록 빈 날짜 문자열 오류 수정 (`src/lib/schemas/voyage.ts`)

**문제**
`EMPTY_FLIGHT.departure_date = ''`, `EMPTY_POLICY.reference_date = ''` 등 날짜 필드의 초기값이 빈 문자열.
Zod `z.string().optional()`은 `''`을 그대로 통과시켜 PostgREST가 `''::date` 캐스팅 시도 → insert 오류 가능성.

**수정**
```ts
const emptyToUndef = z.string().optional().transform(v => v === '' ? undefined : v)
```
`departure_date`, `arrival_date`, `departure_time`, `arrival_time`, `reference_date` 필드에 적용.
`undefined`는 JSON.stringify 시 키 자체가 생략 → DB에 NULL 저장.

### 4. 항차검색 캐시 즉시 갱신 (`src/pages/VoyageSearch.tsx`)

**문제**
VoyageNew는 독립 `QueryClientProvider`를 사용. 새 행사 저장 후 VoyageMaster로 돌아올 때,
VoyageMaster의 `qc`는 `staleTime: 60_000`으로 설정되어 있어 60초 이내에 재방문 시 캐시가
유효한 것으로 판단 → 새로 생성된 행사가 목록에 없어 `selectedVoyage = undefined`,

**수정**
```ts
// 변경 전

// 변경 후

```
`VoyageSearch` 컴포넌트가 마운트될 때마다 항상 최신 행사 목록을 재조회.

### 5. 날짜 관계 검증 추가 (`src/lib/schemas/voyage.ts`)

**문제**
- 귀국일이 출발일보다 앞선 날짜로 저장 가능
- 승선일이 출발일~귀국일 범위를 벗어나도 저장 가능

**수정**
`voyageFormSchema`에 `.superRefine()` 추가:
```ts
.superRefine((data, ctx) => {
  const dep = data.departure_date
  const ret = data.return_date
  const board = data.boarding_date

  if (ret && ret < dep) {
    ctx.addIssue({ code: z.ZodIssueCode.custom, message: '귀국일은 출발일 이후여야 합니다', path: ['return_date'] })
  }
  if (board) {
    if (board < dep) {
      ctx.addIssue({ code: z.ZodIssueCode.custom, message: '승선일은 출발일 이후여야 합니다', path: ['boarding_date'] })
    }
    if (ret && board > ret) {
      ctx.addIssue({ code: z.ZodIssueCode.custom, message: '승선일은 귀국일 이전이어야 합니다', path: ['boarding_date'] })
    }
  }
})
```
ISO 날짜 문자열(`YYYY-MM-DD`)은 문자열 비교만으로 날짜 대소 비교 가능.
에러는 해당 필드 아래 빨간 메시지로 표시 (`BasicInfoSection.tsx`에 이미 `errors.*.message` 렌더링 코드 있음).

## 기술 메모

- **RLS 권한과 프론트엔드 가드는 항상 일치해야 함**: DB 레벨에서 `admin`만 삭제 가능한 경우, UI 버튼도 `isAdmin` 조건으로 제한. `canWrite`(staff+admin)로 버튼을 표시하면 staff가 클릭 후 에러를 겪는 나쁜 UX 발생.
- **ON DELETE CASCADE 확인 습관**: 부모 레코드 삭제 시 하위 테이블 정리는 마이그레이션의 FK 정의로 보장. 별도 삭제 로직 불필요.
- **`z.string().optional()`은 빈 문자열을 통과시킴**: DATE/TIME 컬럼 대상 필드는 반드시 `emptyToUndef` 변환 필요.
- **독립 QueryClient 간 캐시는 공유되지 않음**: 페이지별로 격리된 QueryClient를 사용하는 경우, 데이터 갱신은 각 client 내부에서만 유효. `refetchOnMount: 'always'`로 마운트 시 강제 갱신하거나, 앱 전역 단일 QueryClient 구조로 개선 고려.
- **`tsc --noEmit`은 로컬 파일 기준 검사**: CI 빌드(Vite)는 git에 커밋된 파일 기준이므로, 파일 수정 후 git add까지 확인 필요.
