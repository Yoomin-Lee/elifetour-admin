## 5. SelectOrInput 버그 수정 및 FieldSelect 기반 최종 전환

### 5-1. 1차 이슈 — 기존 DB 값이 목록에 없으면 자동으로 text input 모드가 됨

**원인**: `isCustom` 초기값을 `() => value !== '' && !options.includes(value)`로 설정.  
DB에 "ROYAL"처럼 정의된 목록에 없는 값이 저장된 경우 → 자동으로 text input 모드 진입.

**1차 수정**: `useState(false)` 고정 + 목록에 없는 기존 값은 동적으로 옵션에 삽입.

```typescript
const baseOptions = value !== '' && !options.includes(value)
  ? [value, ...options]
  : options
```

### 5-2. 2차 이슈 — 여전히 브라우저 기본 select UI로 보임

**원인**: `SelectOrInput` 내부에서 options/CUSTOM 선택 시 native `<select>` 렌더링 경로가 있었음.

**최종 수정**: `SelectOrInput` 내부를 `FieldSelect` 완전 기반으로 재작성. 브라우저 native `<select>` 완전 제거.

```tsx
const CUSTOM = '__CUSTOM__'

function SelectOrInput({ value, onChange, options, placeholder = '선택…' }) {
  const [isCustom, setIsCustom] = useState(false)

  if (isCustom) {
    return (
      <div className="flex gap-1">
        <input value={value} onChange={e => onChange(e.target.value)}
          placeholder="직접 입력" autoFocus
          className="input h-7 text-sm flex-1 min-w-0" />
        <button type="button"
          onClick={() => { setIsCustom(false); onChange('') }}
          className="shrink-0 flex h-7 w-7 items-center justify-center rounded-lg border border-slate-200 text-slate-400 hover:bg-slate-100 transition">
          <ChevronDown className="h-3.5 w-3.5" />
        </button>
      </div>
    )
  }

  const baseOptions = value !== '' && !options.includes(value) ? [value, ...options] : options
  const fieldOptions = [...baseOptions, { value: CUSTOM, label: '✏ 직접 입력' }]

  return (
    <FieldSelect
      value={value}
      options={fieldOptions}
      onChange={v => {
        if (v === CUSTOM) { setIsCustom(true); onChange('') }
        else onChange(v)
      }}
      placeholder={placeholder}
      className="h-7 text-sm"
    />
  )
}
```

## 6. 엑셀 데이터 → DB 마이그레이션 SQL

### 배경
크루즈.xlsx 엑셀에 있는 55개 항차의 에이전트, 캐빈등급, 총캐빈, 예약캐빈, 캐빈당 가격 데이터를 DB에 일괄 입력.

Supabase Management API 인증 실패 → SQL 파일로 작성, SQL Editor에서 수동 실행.

### 핵심 이슈 — departure_date 기준 혼동

엑셀에는 두 개의 날짜 컬럼이 존재:
- `행사명` — 예: "25/02/14 싱가포르" → **이 날짜가 DB의 `departure_date`**
- `승선일` — 실제 크루즈 탑승일 (1~2일 뒤)

1차 SQL에서 승선일 기준으로 작성 → 0건 매칭.  
DB 확인으로 행사명 날짜가 `departure_date`임을 확인 후 전체 재작성.

```
행사명: "25/02/14 싱가포르"  →  departure_date: 2025-02-14  ✓
승선일: 2025-02-15             →  DB 없음  ✗
```

### SQL 구조 (3단계)

```sql
-- 1단계: voyages.agent 업데이트 (날짜 + 지역 키워드 매칭)
WITH updates(dep, region_kw, new_agent) AS (VALUES
  ('2025-02-13'::date, '동북아', 'TMK'),
  ('2025-02-14'::date, '싱가포르', 'FLORENCE'),
  -- ...55개 항차
)
UPDATE voyages SET agent = u.new_agent
FROM updates u
WHERE voyages.departure_date = u.dep
  AND voyages.region ILIKE '%' || u.region_kw || '%'
  AND u.new_agent <> '';

-- 2단계: 기존 cabin_grades 삭제 (중복 방지)
DELETE FROM cabin_grades
WHERE voyage_id IN (
  SELECT DISTINCT v.id FROM voyages v
  WHERE v.departure_date IN (/* 전체 날짜 목록 */)
);

-- 3단계: cabin_grades 새로 삽입
INSERT INTO cabin_grades
  (voyage_id, grade, total, reserved, price_per_person, currency, sort_order)
SELECT v.id, d.grade, d.total, d.reserved, d.price, d.currency, d.sort_order
FROM voyages v
JOIN (VALUES
  ('2025-02-13'::date, '동북아', '4D', 22, 14, 1150, 'USD', 0),
  ('2025-02-14'::date, '싱가포르', '4D', 22, 21, 1580, 'USD', 0),
  -- ...76개 캐빈등급 행
) AS d(dep, region_kw, grade, total, reserved, price, currency, sort_order)
ON v.departure_date = d.dep
  AND v.region ILIKE '%' || d.region_kw || '%';
```

### 엣지 케이스 처리

| 케이스 | 처리 방법 |
|--------|-----------|
| 같은 날짜, 다른 지역 | region_kw로 구분 (예: 동북아 vs 알래스카 — 2026-05-16) |
| 캐빈등급 여러 개 | sort_order 0, 1, 2… 로 구분 (예: 2025-03-06 싱가포르: 1D, 4D, 4U) |
| 빈 등급 | `'기본'` 으로 대체 |
| 통화 기준 | 지중해·북유럽·두바이 → EUR / 나머지 → USD |

## 7. 페이지 이동 시 스크롤 위치 초기화

### 증상
상세 정보 바로가기 버튼 클릭 시 이전 페이지의 스크롤 위치가 그대로 유지됨.

### 원인
React Router는 SPA 방식으로 동작하므로 route 변경 시 브라우저가 스크롤을 자동으로 초기화하지 않음.  
특히 pathname이 동일하고 search(쿼리 파라미터)만 바뀌는 경우(`/voyages?voyage=xxx`)도 포함.

### 해결
`ScrollToTop` 컴포넌트를 `App.jsx`에 삽입 — `pathname` 또는 `search` 변경 시 `window.scrollTo(0, 0)` 호출.

```jsx
// src/components/ScrollToTop.jsx
import { useEffect } from 'react'
import { useLocation } from 'react-router-dom'

export default function ScrollToTop() {
  const { pathname, search } = useLocation()
  useEffect(() => {
    window.scrollTo(0, 0)
  }, [pathname, search])
  return null
}
```

```jsx
// App.jsx — AuthProvider 내부 최상단에 배치
<AuthProvider>
  <ScrollToTop />
  <Toaster ... />
  <Routes>...</Routes>
</AuthProvider>
```
