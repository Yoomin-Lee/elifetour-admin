### 1. 취소료 D-day 날짜 계산 하루 오차 수정

#### 배경

항차 상세 > 취소료 섹션에서 기준일 대비 D-day 날짜가 하루씩 당겨져 표시되는 오류 발견.
예) 26/10/01 서부지중해 기준 D-30 → 실제 8/31이어야 하는데 9/1로 표시.

#### 원인

`dMinusToDate` 함수에서 `toISOString().slice(0, 10)` 사용 시, `toISOString()`이 UTC 기준으로 변환되어 KST(UTC+9) 자정이 전날 UTC로 계산되는 문제.

#### 수정 (`CancellationCard.tsx`)

```typescript
// 수정 전 (UTC 오차 발생)
const d = new Date(refDate)
return d.toISOString().slice(0, 10)

// 수정 후 (로컬 날짜 메서드 사용)
const d = new Date(refDate + 'T00:00:00')
d.setDate(d.getDate() - dMinus)
const mm = String(d.getMonth() + 1).padStart(2, '0')
const dd = String(d.getDate()).padStart(2, '0')
return `${mm}.${dd}`
```

### 5. Supabase 자동 DB 백업 설정

#### 배경

장기 운영 안정성을 위해 데이터 유실 방지 목적으로 매일 자정 자동 백업 설정.

#### 시도 경과

| 시도 | 방법 | 결과 |
|------|------|------|
| 1차 | `pg_dump` 직접 연결 | IPv6 전용 호스트 — GitHub Actions 접근 불가 |
| 2차 | Supabase CLI `db dump` | CLI 버전 플래그 불일치, 프로젝트 링크 필요 |
| 3차 | 연결 풀러(Supavisor) pg_dump | tenant not found 오류 |
| 4차 | `gai.conf` IPv4 강제 | 효과 없음 (A 레코드 자체 없음) |
| 5차 | REST API + service_role 키 | **성공** ✅ |

#### 최종 구현 (`.github/workflows/backup.yml`)

- **방식**: Supabase JS 클라이언트 + service_role 키로 HTTPS 경유 전체 테이블 JSON 내보내기
- **스케줄**: 매일 00:00 KST (15:00 UTC) 자동 실행
- **보관**: GitHub Actions artifact, 90일 보관
- **수동 실행**: `workflow_dispatch` 지원

**백업 대상 테이블 (15개)**

`eli_profiles`, `voyages`, `itinerary_days`, `voyage_flights`, `flights`, `cabin_grades`, `cancellation_policies`, `eli_cancellation_presets`, `eli_itinerary_presets`, `airline_options`, `region_options`, `hotels`, `payment_schedules`, `history_logs`, `mn_sections`

**첫 실행 결과 (수동 테스트)**

- 15개 테이블 전체 성공
- 총 992행 내보내기 완료

#### 필요 GitHub Secret

| 시크릿 이름 | 용도 |
|-------------|------|
| `SUPABASE_SERVICE_ROLE_KEY` | 테이블 전체 열람 (RLS 우회) |
