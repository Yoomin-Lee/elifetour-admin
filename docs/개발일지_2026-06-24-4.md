## 변경 사항

### 1. 캐빈가 소수점 입력 허용 (`src/components/voyages/CabinPriceSection.tsx`)

**문제**  
CCF / NCCF / TAX / TIP 입력 필드가 `type="number"` 이지만 `step` 속성 없음 → 브라우저 기본값 `step=1` 적용 → 소수점 입력 차단.

**수정**
```tsx
// 변경 전
<Input type="number" min={0} {...register(`cabin_grades.${index}.${f}`)} />

// 변경 후
<Input type="number" min={0} step="0.01" {...register(`cabin_grades.${index}.${f}`)} />
```
`step="0.01"` 추가로 소수점 2자리까지 입력 가능. Zod 스키마는 이미 `z.coerce.number()`로 소수 허용 상태.

### 2. 기항지 비용(인당) 소수점 입력 허용 (`src/components/voyages/ItineraryEditor.tsx`)

**문제**  
기항지 일정의 비용(인당) 필드에 `type="number"` 없이 텍스트 input 사용. `onChange`에서 즉시 `Number(e.target.value)` 변환 → `"1."` 입력 시 `Number("1.")` = `1`로 소수점이 사라짐.

**수정**
```tsx
// 변경 전
<Input
  value={field.value ?? ''}
  onChange={e => field.onChange(e.target.value === '' ? null : Number(e.target.value))}
/>

// 변경 후
<Input
  type="number" min={0} step="0.01"
  value={field.value ?? ''}
  onChange={e => field.onChange(e.target.value === '' ? null : Number(e.target.value))}
/>
```
`type="number"` + `step="0.01"` 추가. 브라우저 네이티브 number input이 소수점 중간 상태를 관리하므로 onChange의 Number 변환과 충돌 없음.

### 3. DatePicker 숫자 빠른 입력 (`src/components/ui/date-picker.tsx`)

**요구사항**  
`240110` 입력 → `2024-01-10` 자동 변환. 달력 드롭다운도 기존대로 사용 가능.

**구현**

트리거를 `<button>`에서 `<input> + 달력 아이콘 버튼` 조합으로 교체.

```tsx
const [quickEntry, setQuickEntry] = useState<string | null>(null)
// null = 보기 모드, string = 숫자 입력 중

function handleInputKeyDown(e: React.KeyboardEvent<HTMLInputElement>) {
  if (e.key === 'Backspace') { ... }
  if (!/^[0-9]$/.test(e.key)) return
  e.preventDefault()

  const newEntry = (quickEntry ?? '') + e.key
  setQuickEntry(newEntry)

  if (newEntry.length === 6) {
    // YYMMDD → YYYY-MM-DD 변환 및 날짜 유효성 검증
    tryConvert(newEntry)   // new Date() 객체로 유효성 확인 후 onChange 호출
    setQuickEntry(null)
    inputRef.current?.blur()
  }
}
```

**`tryConvert` 로직**
```ts
function tryConvert(entry: string) {
  const year  = 2000 + Number(entry.slice(0, 2))
  const month = Number(entry.slice(2, 4))
  const day   = Number(entry.slice(4, 6))
  const date  = new Date(year, month - 1, day)
  // Date 객체가 동일한 년/월/일을 반환하면 유효한 날짜
  if (date.getFullYear() === year && date.getMonth() === month - 1 && date.getDate() === day) {
    onChange(`${year}-${String(month).padStart(2, '0')}-${String(day).padStart(2, '0')}`)
    setViewDate(date)
  }
}
```

**UX 흐름**
- 필드 클릭 → 플레이스홀더 `YYMMDD` 표시 → 숫자 입력 중 해당 digit 표시
- 6자리 완성 → 자동 변환 후 입력 모드 종료
- Backspace → 마지막 digit 삭제
- Escape → 입력 취소
- 달력 아이콘 클릭 → 기존 달력 팝업 열기

**적용 범위**  
`DatePicker` 컴포넌트 자체를 수정했으므로, 이를 사용하는 모든 곳에 자동 적용:
- `BasicInfoSection` (출발일/귀국일/승선일)
- `FlightsEditor` / `FlightsTab` / `FlightsCard` (출발일/도착일)
- `ItineraryEditor` / `ItineraryCard` (기항지 날짜)
- `CancellationEditor` (취소료 기준일)
- `ShoreTab` / `HotelTab` / `PaymentTab`
- `PassengerForm` / `TripForm`

### 4. TimePicker 두 자리 입력 버그 수정 (`src/components/ui/time-picker.tsx`)

**문제**  
기존 `onChange` 기반 처리에서 React controlled input의 커서 재설정 이슈 발생. 첫 번째 digit("1") 입력 후 React 재렌더 시 커서가 처음으로 이동 → 두 번째 digit("4") 입력 시 "41"이 되어 `Math.min(41, 23)` = `"23"` 으로 잘못 처리될 수 있음.

**수정: `onKeyDown` 기반으로 재작성**

`onChange` 이벤트를 완전히 버리고 `onKeyDown` + `e.preventDefault()`로 모든 digit 입력을 제어.
DOM 자체에 문자 삽입이 발생하지 않으므로 커서 위치와 무관하게 동작.

```tsx
const hhCount = useRef(0)   // 포커스 이후 입력한 digit 수
const hhFirst = useRef('')  // 첫 번째 digit 저장 (stale closure 방지)

function handleHhKeyDown(e: React.KeyboardEvent<HTMLInputElement>) {
  if (e.key === 'Backspace') { e.preventDefault(); setHh(''); ... return }
  if (e.key === 'ArrowRight') { /* MM으로 이동 */ return }
  if (!/^[0-9]$/.test(e.key)) return
  e.preventDefault()

  if (hhCount.current === 0) {
    if (Number(digit) > 2) {
      // 3 이상 → '0X' 자동 패딩 후 MM으로 이동
      setHh('0' + digit); commit('0' + digit, mm); mmRef.current?.focus()
    } else {
      hhFirst.current = digit; setHh(digit); hhCount.current = 1
    }
  } else {
    // 두 번째 digit: state 아닌 ref에서 조합 (stale closure 방지)
    const val = Math.min(Number(hhFirst.current + digit), 23).toString().padStart(2, '0')
    setHh(val); commit(val, mm); mmRef.current?.focus()
  }
}
```

`hhFirst.current`를 쓰는 이유: 첫 번째 digit 입력 후 React 재렌더 전에 두 번째 keydown이 오면 `hh` state가 아직 갱신되지 않은 상태(stale closure). ref는 렌더 사이클과 무관하게 동기적으로 갱신됨.

**추가 개선**
- `ArrowLeft` / `ArrowRight`로 HH ↔ MM 간 이동
- `onFocus` 시 카운터 초기화 → 재포커스 시 처음부터 새로 입력
- MM도 동일한 패턴 적용 (6 이상 digit → '0X' 자동 패딩)

**소요시간 자동계산 호환성 확인**  
`TimePicker.onChange`는 `commit()` 함수에서만 호출되며 포맷은 `"HH:MM"` 그대로 유지. `useFlightCalc` → `calcFlightDuration` → `normalizeTime(raw.slice(0, 5))` 체인에 변경 없음. 정상 동작 확인.

## 기술 메모

- **`type="number"` + `step` 속성**: `step` 기본값은 `1`. 소수점 입력을 허용하려면 `step="0.01"` 등 명시 필요. `step`은 화살표 버튼 증감 단위도 결정함.
- **React controlled input 커서 이슈**: `onChange`로 state를 업데이트하면 React 재렌더 시 커서 위치가 초기화될 수 있음. 특히 짧은 문자열(1~2자) 입력 필드에서 빈번히 발생. `onKeyDown` + `e.preventDefault()`로 DOM 직접 조작을 막고 state만 업데이트하면 회피 가능.
- **stale closure vs ref**: `onKeyDown` 핸들러는 렌더 시점의 state 값을 클로저로 캡처. 빠른 연타 시 이전 렌더의 핸들러가 오래된 state를 참조할 수 있음. `useRef`는 항상 최신값을 가리키므로 이 문제를 해결함.
- **단일 컴포넌트 수정 → 전체 적용**: 공유 UI 컴포넌트(`DatePicker`, `TimePicker`)를 수정하면 import하는 모든 페이지에 즉시 반영. 개별 파일 수정 불필요.
