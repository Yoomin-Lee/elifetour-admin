### 1. 결제 스케줄 — 에이전트별 열 추가·드래그 재정렬·DB 순서 저장

#### 배경

결제 스케줄 테이블(크루즈/항공/호텔/랜드/보험 5열)에서 동일 카테고리라도 에이전트(협력업체)마다 결제 조건이 달라 별도 열로 관리해야 하는 요구 발생. 열 추가 외에 팀원 간 열 순서 공유와 드래그 재정렬도 함께 구현.

#### DB 변경

**마이그레이션 (`20260701000000_payment_agent_columns.sql`)**

```sql
-- 1. payment_schedules 에 agent_id 추가
ALTER TABLE payment_schedules
  ADD COLUMN IF NOT EXISTS agent_id text NOT NULL DEFAULT 'default';

-- 2. 유니크 제약: (voyage_id, category, payment_type, section) →
--                  (voyage_id, category, payment_type, section, agent_id)
ALTER TABLE payment_schedules
  DROP CONSTRAINT IF EXISTS payment_schedules_voyage_id_category_payment_type_section_key;
ALTER TABLE payment_schedules
  ADD CONSTRAINT payment_schedules_voyage_category_pt_section_agent_key
  UNIQUE (voyage_id, category, payment_type, section, agent_id);

-- 3. 열 순서 팀 공유 저장용 JSONB 컬럼
ALTER TABLE voyages
  ADD COLUMN IF NOT EXISTS payment_col_order jsonb;
```

**RPC 함수: `delete_payment_agent_column(p_voyage_id, p_agent_id)`**

에이전트 열 삭제 시 두 작업을 단일 트랜잭션으로 처리:
1. `payment_schedules`에서 해당 `agent_id` 행 전부 삭제
2. `voyages.payment_col_order` 배열에서 해당 항목 제거

```sql
CREATE OR REPLACE FUNCTION delete_payment_agent_column(p_voyage_id uuid, p_agent_id text)
RETURNS void LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  IF p_agent_id = 'default' THEN
    RAISE EXCEPTION 'default 열은 삭제할 수 없습니다';
  END IF;
  DELETE FROM payment_schedules
    WHERE voyage_id = p_voyage_id AND agent_id = p_agent_id;
  UPDATE voyages
  SET payment_col_order = (
    SELECT COALESCE(jsonb_agg(el ORDER BY ord), '[]'::jsonb)
    FROM jsonb_array_elements(COALESCE(payment_col_order, '[]'::jsonb))
      WITH ORDINALITY AS t(el, ord)
    WHERE el->>'agentId' != p_agent_id
  )
  WHERE id = p_voyage_id;
END;
$$;
GRANT EXECUTE ON FUNCTION delete_payment_agent_column(uuid, text) TO authenticated;
```

**에이전트 열 추가**

```ts
function addAgentColumn(baseCategory: PaymentCategory) {
  const agentId = crypto.randomUUID()
  const colId   = `${baseCategory}_${agentId}`
  const newCol  = { colId, baseCategory, agentId, label: CATEGORY_LABEL[baseCategory] }

  setColumns(prev => {
    // 같은 baseCategory 마지막 열 뒤에 삽입
    const lastIdx = prev.reduce((acc, c, i) => c.baseCategory === baseCategory ? i : acc, -1)
    const next = [...prev]
    next.splice(lastIdx + 1, 0, newCol)
    colOrderMut.mutate(next)   // DB 즉시 저장
    return next
  })
  setTimeout(() => setEditingLabel(colId), 50)  // 추가 직후 레이블 편집 자동 진입
}
```

**원자적 열 삭제**

```ts
const deleteAgentColMut = useMutation({

})
```

**가로 스크롤 / 열 너비**


| 기능 | 동작 |
|------|------|
| + 에이전트 추가 | 해당 카테고리 마지막 열 바로 뒤에 빈 열 삽입, 레이블 편집 자동 진입 |

### 2. 결제 스케줄 — 기본 5열 레이블 인라인 편집 허용

#### 배경

에이전트 추가 열뿐만 아니라 기본 5열(크루즈/항공/호텔/랜드/보험)의 태그명도 팀 상황에 맞게 변경 가능해야 한다는 요청.

#### 수정 (`SortableColumnHeader`)

```tsx
// 변경 전: isAgent 조건부 편집
onClick={() => isAgent && setEditingLabel(col.colId)}
className={`... ${isAgent ? 'cursor-pointer hover:ring-2 ...' : ''}`}

// 변경 후: 모든 열 편집 가능
onClick={() => setEditingLabel(col.colId)}
className="... cursor-pointer hover:ring-2 hover:ring-offset-1 hover:ring-brand/40 transition"
```

삭제 버튼(`X`)은 여전히 에이전트 열(`agentId !== 'default'`)에만 표시.

### 3. 전역 스크롤바 네이비 통일

#### 배경

결제 스케줄 가로 스크롤바에 네이비 색상 적용 후, 모든 탭/페이지 스크롤바를 동일 스타일로 통일하는 요청.

#### 수정 (`src/index.css`)

파일별 패치 대신 전역 CSS 규칙으로 일괄 적용:

```css
@layer base {
  /* 전역 스크롤바 네이비 통일 */
  * {
    scrollbar-width: thin;
    scrollbar-color: #0F4C8A transparent;
  }
  *::-webkit-scrollbar { width: 4px; height: 4px; }
  *::-webkit-scrollbar-track { background: transparent; }
  *::-webkit-scrollbar-thumb {
    background-color: #0F4C8A;
    border-radius: 99px;
  }
}
```

- `width: 4px` — 세로 스크롤바 너비
- `height: 4px` — 가로 스크롤바 높이 (기존 `.scrollbar-navy`에 누락되어 있던 항목)
- 기존 `scrollbar-none` 클래스(탭바 등)는 selector 우선순위가 높아 영향 없음
