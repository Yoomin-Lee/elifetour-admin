# 개발일지 — 2026-06-15 (4차)

## 진행 내용

### Phase 2 — 예약 단계 트래킹 (문의→계약→잔금→여권→출발)

---

### 1. 배경 및 목적

기존 여행자 명단에는 결제 상태(미납/일부납/완납)만 있었고, 예약의 전체 흐름을 파악할 수 없었음.

직원이 고객 한 명의 진행 상태를 보려면 메모나 별도 시트를 확인해야 했음.

→ 여행자별로 예약 단계를 DB에 관리하고, 테이블에서 즉시 변경 가능하도록 구현.

---

### 2. 예약 단계 정의 (5단계)

| 단계 | 값 | 색상 | 의미 |
|------|----|------|------|
| 문의 | `inquiry` | 회색 | 초기 문의 접수 |
| 계약 | `confirmed` | 파란색 | 예약 확정, 계약 체결 |
| 잔금 | `balance` | 보라색 | 잔금 납부 완료 |
| 여권 | `passport` | 주황색 | 여권 수령/확인 완료 |
| 출발 | `departed` | 초록색 | 출발 완료 |

---

### 5. TripDetail.jsx 주요 변경

#### 인라인 드롭다운 (즉시 변경)

테이블 예약단계 셀에 `<select>` 인라인 배치.
저장 버튼 없이 선택 즉시 `updatePassenger()` 호출 → DB 반영.

```jsx
<select
  value={p.booking_status || 'inquiry'}
  onChange={(e) => handleBookingStatus(p.id, e.target.value)}
  disabled={updatingBooking === p.id}
>
  {statusOptions.booking.map(o => <option ...>{o.label}</option>)}
</select>
```

#### 명단 통계 (단계별 인원 수)

```
문의 3 · 계약 2 · 잔금 1 · 여권 0 · 출발 0
```

기존 결제 통계 아래에 예약 단계별 인원 수 추가.

#### 모바일 카드

이름 옆에 예약단계 배지 + 결제 배지 나란히 표시.

#### CSV 내보내기

`예약단계` 컬럼 포함.
