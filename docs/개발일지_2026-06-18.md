## 1. 사용자 승인 시스템

### 배경

Google OAuth로 누구나 로그인할 수 있어 내부 직원이 아닌 외부인이 서비스에 접근할 위험이 있었음.  
신규 가입자는 관리자 승인 후에만 서비스를 이용할 수 있도록 승인 게이트 추가.

---

### DB 변경

#### `eli_profiles` 컬럼 추가

```sql
ALTER TABLE eli_profiles
  ADD COLUMN IF NOT EXISTS status text NOT NULL DEFAULT 'pending';

-- 기존 유저 전원 approved 처리 (서비스 단절 방지)
UPDATE eli_profiles SET status = 'approved' WHERE status = 'pending';
```

- `status`: `pending`(대기) / `approved`(승인), 신규 가입 시 기본값 `pending`

#### 관리자 RLS 정책 추가

```sql
-- 재귀 방지용 security definer 함수
CREATE OR REPLACE FUNCTION eli_is_admin()
RETURNS boolean LANGUAGE sql SECURITY DEFINER STABLE AS $$
  SELECT EXISTS(SELECT 1 FROM eli_profiles WHERE id = auth.uid() AND role = 'admin');
$$;

-- 관리자는 모든 프로필 조회·수정 가능
CREATE POLICY "admin all profiles"
  ON eli_profiles FOR ALL
  USING (eli_is_admin()) WITH CHECK (eli_is_admin());
```

기존 "own profile" 정책은 자신의 행만 허용하므로, 관리자가 전체 직원 목록을 조회·수정하려면 별도 정책 필요.  
`SECURITY DEFINER` 함수로 RLS 재귀 호출 문제 회피.

### 프론트엔드 변경

#### AuthContext (`src/context/AuthContext.jsx`)

```jsx
const status = profile?.status ?? 'pending'
const isPending = profile !== null && status !== 'approved'
```

- `status`, `isPending` 값을 Context에 추가 노출

#### ProtectedRoute (`src/App.jsx`)

```jsx
function ProtectedRoute({ children }) {
  const { user, isPending, loading } = useAuth()
  if (loading) return <Spinner />
  if (!user) return <Navigate to="/login" replace />
  if (isPending) return <Navigate to="/pending" replace />   // ← 추가
  return children
}
```

- 인증은 됐으나 미승인 유저 → `/pending` 차단 페이지로 리다이렉트

### 흐름 요약

```
신규 Google 로그인
  → eli_handle_new_user 트리거 → status='pending' 으로 프로필 생성
  → ProtectedRoute: isPending=true → /pending 차단 화면
  → 관리자가 /users 에서 "승인" 버튼 클릭 (역할 선택 후)
  → status='approved' 업데이트
  → 다음 로그인부터 정상 접근
```

## 2. 직원 관리 페이지 UI 개선

### 변경 전

- 승인된 직원 행에 인라인 `<select>` 드롭다운으로 역할 변경
- 본인 계정(`나`)은 배지(읽기 전용)만 표시 → 이름 변경 불가
- 승인 버튼이 바로 `staff`로 고정 승인

### 변경 후

#### 승인 대기 섹션

- "승인" 버튼 클릭 → **ApproveModal** 팝업
- 역할(관리자/직원/인솔자) 선택 후 "승인하기"

#### 승인된 직원 섹션

- 역할 컬럼은 배지(읽기 전용)로 통일
- 각 행 우측 **"수정" 버튼** 추가 → **EditModal** 팝업
  - 이름(`display_name`) 수정
  - 역할 드롭다운 변경
  - 본인 계정의 역할을 관리자 이외로 변경 시 경고 문구 표시
