## 변경 사항

### 1. 새행사등록 → 항공 탭 자동 미러링

#### 배경
기존에 `flights` 테이블(새행사등록·항차상세 전용)과 `voyage_flights` 테이블(항공 탭 전용)은 완전히 분리되어 있었음. 새행사등록에서 항공 정보를 입력해도 항공 탭에 나타나지 않는 문제.

#### 해결 방식
`createVoyageWithChildren`(`voyages.ts`)이 `flights` 테이블에 저장한 뒤, `voyage_flights`에도 동일 데이터를 자동 미러링.

**필드 매핑:**

| flights 필드 | voyage_flights 필드 | 변환 |
|-------------|---------------------|------|
| segments[].flight_no | flight_num | 직접 매핑 |
| segments[].origin | dep_airport | IATA 코드 추출 |
| segments[].destination | arr_airport | IATA 코드 추출 |
| segments[].departure_date/time | departureDate/Time → dep_datetime | TIMESTAMPTZ 변환 (DST 반영) |
| segments[].arrival_date/time | arrivalDate/Time → arr_datetime | 동일 |
| seats_group/indivi/business | 동일 | 직접 매핑 |
| fare_base/fuel/tax | 동일 | 직접 매핑 |

**구간 우선순위:**
- `segments` 배열이 있으면 → 구간별로 각각 1개씩 `voyage_flights` 레코드 생성
- `segments` 없고 flat 필드(flight_no, origin 등)가 있으면 → flat 필드를 단일 구간으로 취급

**IATA 코드 추출 (`extractIata`):**
```ts
function extractIata(str: string | null | undefined): string {
  const m = str?.match(/\(([A-Z]{3})\)/)
  return m ? m[1] : str?.trim().toUpperCase().slice(0, 3) ?? ''
}
// "인천(ICN)" → "ICN", "BCN" → "BCN"
```

**오류 처리:**
IATA 코드 추출 실패, 날짜 누락, 타임존 계산 오류 시 해당 구간 미러링만 스킵. `try-catch`로 감싸 main save(flights 저장)에 영향 없음.

```ts
try {
  await insertVoyageFlight({ ... })
} catch { /* 미러링 실패는 무시 */ }
```

#### `insertVoyageFlight` 수정 (`voyageFlights.ts`)

기존 `insertVoyageFlight`가 seats/fare 6개 필드를 insert에서 누락하고 있었음 → 수정:

```ts
// Before: seats/fare 필드 없음
.insert({ voyage_id, flight_num, dep_airport, ..., sort_order })

// After: 6개 필드 추가
.insert({ ..., seats_group, seats_indivi, seats_business,
               fare_base, fare_fuel, fare_tax })
```

## 특이사항

- **미러링 조건**: 구간에 dep_airport, arr_airport, departure_date, departure_time이 모두 있어야 함. 이 중 하나라도 없으면 해당 구간은 미러링되지 않음 (항공 탭에 표시 안됨).
- **IATA 형식**: origin/destination 필드가 "인천(ICN)" 형식이어야 정확한 IATA 추출 가능. 단순 한글만 입력하면 앞 3자리를 IATA로 취급해 타임존 계산이 부정확해질 수 있음.
- **기존 데이터**: 미러링은 신규 등록분부터 적용. 기존 flights 데이터는 voyage_flights에 소급 적용되지 않음.
