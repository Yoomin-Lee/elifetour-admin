## 1. 승선일 기항지 자동입력 버튼

### 배경
크루즈 항차의 승선일(`boarding_date`)은 출발일(`departure_date`)과 다른 경우가 많음.  
기항지 일정(ItineraryDay)에서 `summary`에 "승선"이 포함된 행의 날짜를 자동으로 감지해 입력.

### 구현

```tsx
function detectBoardingDate(itinerary?: ItineraryDay[]): string | null {
  if (!itinerary?.length) return null
  const sorted = [...itinerary].sort((a, b) => a.sort_order - b.sort_order)
  const found = sorted.find(d => (d.summary ?? '').includes('승선'))
  return found?.date ?? null
}
```

OverviewCard 편집 모드의 승선일 DatePicker 옆에 버튼 배치:
- 감지된 날짜와 현재 값이 **다를 때**: 시안색 버튼 `기항지 자동입력 (YYYY-MM-DD)` 클릭 시 입력
- 이미 **일치할 때**: 초록색 `✓ 일치` 텍스트 표시

### 변경 파일
`src/components/voyages/OverviewCard.tsx`

## 2. PDF 승선일 일괄 DB 업데이트

### 배경
크루즈.pdf 파일에 54개 항차의 승선일(하선일 포함) 정보가 표 형태로 존재.  
수기 입력 대신 PDF를 직접 읽어 SQL UPDATE 문 일괄 생성.

### 핵심 이슈 — 테이블명 오류

마이그레이션 파일에 `eli_voyages`로 작성 → 실제 테이블명은 `voyages`.  
`eli_` 접두사는 `eli_profiles`, `eli_trips`, `eli_passengers`에만 적용됨.

```sql
-- 오류
ALTER TABLE eli_voyages ADD COLUMN IF NOT EXISTS boarding_date DATE;

-- 수정
ALTER TABLE voyages ADD COLUMN IF NOT EXISTS boarding_date DATE;
```

### 마이그레이션 2개 실행

| 파일 | 내용 |
|------|------|
| `20260622000002_voyage_boarding_date.sql` | `voyages.boarding_date DATE` 컬럼 추가 |
| `20260622000003_backfill_boarding_dates.sql` | 54개 항차 승선일 일괄 UPDATE |

### 엣지 케이스

| 항차 | departure_date | boarding_date | 특이사항 |
|------|---------------|---------------|---------|
| 미서부 | 2026-02-27 | 2026-03-02 | LA 비행 후 3일 뒤 승선 |
| 알래스카 | 2026-05-16 | 2026-05-17 | 같은 날짜 항차가 2개 — 지역 키워드로 구분 |

동일 departure_date인 경우 `region ILIKE` 조건을 추가해 구분:
```sql
UPDATE voyages SET boarding_date = '2026-05-17'
WHERE departure_date = '2026-05-16' AND region ILIKE '%알래스카%';
```

## 5. 항차 상세 검색 — 상태 필터 드롭다운

### 배경
항차 상세(`VoyageSearch`) 페이지에 연도 드롭다운만 있어 상태별 필터가 불가능.  
항차 마스터(`VoyageSearch`) 검색 기능과 동일한 방식으로 상태 드롭다운 추가.

### 구현

```tsx
const [statusFilter, setStatusFilter] = useState<string>('ALL')

const filteredVoyages = voyages.filter(v => {
  const yearOk = yearFilter === 'ALL' || v.departure_date?.startsWith(yearFilter)
  const statusOk = statusFilter === 'ALL' || v.status === statusFilter
  return yearOk && statusOk
})
```

`FieldSelect` 컴포넌트로 연도 드롭다운 바로 옆에 배치:
```tsx
<FieldSelect
  value={statusFilter}
  options={[
    { value: 'ALL', label: '전체 상태' },
    '미오픈', '판매중', '마감', '출발완료', '취소',
  ]}
  onChange={v => {
    setStatusFilter(v)
    if (selectedId && !filteredVoyages.find(x => x.id === selectedId)) {
      setSelectedId(null)
    }
  }}
/>
```

상태 필터 변경 시 현재 선택된 항차가 필터에서 벗어나면 자동으로 선택 해제.

## 6. 취소료 행별 기준일 직접 지정

### 배경
항공이 2개거나 크루즈가 2개인 상품처럼 날짜가 다른 구간이 복수로 존재하는 경우,  
기존 카테고리 기반 D-day 계산(항공→출발일, 크루즈→승선일)으로는 구간별 기준일을 다르게 설정할 수 없음.

### 해결책
`cancellation_policies`에 `reference_date DATE` 컬럼 추가 — 행별로 기준일을 직접 지정.

### 마이그레이션

```sql
-- 20260622000004_cancellation_reference_date.sql
ALTER TABLE cancellation_policies
  ADD COLUMN IF NOT EXISTS reference_date DATE;
```

### D-day 우선순위

```
reference_date (직접 지정) → 크루즈 카테고리 → boarding_date → departure_date
```

```ts
function dMinusForPolicy(p, departureDate, boardingDate) {
  if (p.reference_date) return dMinus(p.reference_date)         // 1순위: 직접 지정
  if (isCruiseCat(p.category) && boardingDate) return dMinus(boardingDate)  // 2순위: 승선일
  return dMinus(departureDate)                                   // 3순위: 출발일
}
```

### UI 변경

- **CancellationCard 편집 모드**: 각 행에 "기준일 직접 지정" 날짜 입력 + ✕ 초기화 버튼
- **CancellationTab 편집 폼**: 동일하게 날짜 입력 + ✕ 버튼
- **CancellationTab 읽기 모드**: "기준일" 컬럼에 직접 지정된 경우 `(직접)` 시안색 표시
- **CancellationEditor** (신규 항차 생성): 정책 행에 기준일 날짜 입력 필드 추가
