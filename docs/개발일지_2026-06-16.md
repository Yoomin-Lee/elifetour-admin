### 2. 결제 스케줄 DB 설계

#### `payment_schedules` 테이블

```sql
CREATE TABLE payment_schedules (
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  voyage_id     uuid        NOT NULL REFERENCES voyages(id) ON DELETE CASCADE,
  category      text        NOT NULL CHECK (category IN ('CRUISE','FLIGHT','HOTEL')),
  payment_type  text        NOT NULL CHECK (payment_type IN ('DEPOSIT_1ST','DEPOSIT_2ND','BALANCE')),
  amount        numeric     NOT NULL DEFAULT 0,
  currency      text        NOT NULL DEFAULT 'KRW',
  due_date      date        NOT NULL,
  is_completed  boolean     NOT NULL DEFAULT false,
  memo          text,
  UNIQUE (voyage_id, category, payment_type)
);
```

- 행사당 최대 9개 레코드 (3 카테고리 × 3 결제 유형) — UNIQUE 제약으로 보장
- `ON DELETE CASCADE`: 행사 삭제 시 결제 스케줄 자동 삭제
- RLS: 읽기=authenticated, 쓰기/수정/삭제=admin/staff

#### 대용량 성능 최적화 — 인덱스

```sql
CREATE INDEX IF NOT EXISTS idx_payment_schedules_due_date  ON payment_schedules (due_date);
CREATE INDEX IF NOT EXISTS idx_payment_schedules_voyage_id ON payment_schedules (voyage_id);
```

월별 필터링 쿼리(`gte/lte`)가 풀스캔 없이 인덱스를 타도록 설계.
Realtime publication도 추가하여 실시간 동기화 지원.

### 4. CRUD 쿼리 함수 (`src/lib/queries/paymentSchedules.ts`)

| 함수 | 설명 |
|------|------|
| `fetchPaymentSchedules(voyageId)` | 행사별 전체 조회 |
| `fetchPaymentSchedulesByMonth(year, month)` | 달력용 월별 동적 페칭 |
| `upsertPaymentSchedule(payload)` | 저장/수정 (UNIQUE 충돌 시 UPDATE) |
| `deletePaymentSchedule(id)` | 삭제 |
| `togglePaymentCompleted(id, is_completed)` | 완료 토글 |

`fetchPaymentSchedulesByMonth`는 `.gte()` / `.lte()` 필터로 해당 월 데이터만 조회:

```ts
.gte('due_date', `${year}-${pad(month)}-01`)
.lte('due_date', `${year}-${pad(month)}-${pad(lastDay)}`)
```

### 6. 달력 탭 결제 마감일 통합 (`src/components/voyages/tabs/CalendarTab.tsx`)

#### 동적 페칭 + 성능 최적화

```ts
const currentYear  = currentDate.getFullYear()
const currentMonth = currentDate.getMonth() + 1

const { data: payments = [] } = useQuery({
  queryKey: ['payment-schedules-month', currentYear, currentMonth],
  queryFn: () => fetchPaymentSchedulesByMonth(currentYear, currentMonth),
  staleTime: 60_000,
})
```

월 변경 시 `queryKey`가 바뀌어 자동 리페치. 전체 데이터 로드 없음.

#### useMemo 적용 항목

| 상태 | 메모이제이션 의존성 |
|------|-------------------|
| `days` (달력 날짜 배열) | `currentDate` |
| `voyagesByDay` (Map) | `voyages`, `days` |
| `paymentsByDay` (Map) | `payments` |
| `voyagesThisMonth` | `voyages`, `currentDate` |
| `paymentsThisMonth` | `payments` |

날짜별 lookup을 `Map`으로 처리해 O(n) → O(1) 개선.

#### 달력 셀 표시

- 행사 이벤트: 실선 테두리, 상태별 색상, 출발일(출) / 귀국일(귀) 뱃지
- 결제 마감일: **점선 테두리**, 카테고리별 색상(크루즈=cyan, 항공=amber, 호텔=emerald)
- 완료된 마감: 흐림+취소선 처리

#### 하단 패널 (3열)

- **범례**: 행사 상태 색상 + 결제 카테고리 색상
- **이번 달 출발 행사**: 출발일 오름차순
- **이번 달 결제 마감**: 마감일 오름차순, 완료 시 체크 아이콘

### 9. 항공 탭 정렬 개선

#### 문제

항공편 자체 출발일 기준 정렬 시 같은 행사의 출국편·귀국편이 다른 행사 편들과 섞임.

예: `27/03/12 싱가포르 출국 → 27/03/08 싱가포르 출국 → 27/03/12 싱가포르 귀국`

#### 해결

3단계 정렬:

```ts
.sort((a, b) => {
  // 1. 행사 출발일 최신순
  const aVoy = a.voyages?.departure_date ?? ''
  const bVoy = b.voyages?.departure_date ?? ''
  if (aVoy !== bVoy) return bVoy.localeCompare(aVoy)
  // 2. 항공사 코드 알파벳순 (편명 앞 영문자)
  const aAirline = a.flight_num.match(/^[A-Za-z]+/)?.[0] ?? ''
  const bAirline = b.flight_num.match(/^[A-Za-z]+/)?.[0] ?? ''
  if (aAirline !== bAirline) return aAirline.localeCompare(bAirline)
  // 3. 출발시간 오름차순
  return new Date(a.dep_datetime).getTime() - new Date(b.dep_datetime).getTime()
})
```

결과: `KE 출국 → KE 입국 → SQ 출국 → SQ 입국` 순 정렬.
새 항공편 추가 시 자동 적용 (프론트엔드 렌더링 시마다 실행).
