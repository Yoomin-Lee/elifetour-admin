## 변경 사항

### 1. 항차 검색 목록 항공사 표시 (`src/components/voyages/VoyageCombobox.tsx`)

**배경**  
항차 상세 개요 탭에서 항공 · 왕복항공 2개를 각각 다르게 설정할 수 있음에도, 항차 검색 드롭다운 목록에는 항공사 정보가 전혀 표시되지 않아 확인이 불가능했음.

**변경 내용**  
각 항차 목록 아이템에 항공사 정보를 이름 아래 작은 회색 텍스트로 추가.

```typescript
function airlineLabel(v: Voyage): string | null {
  const a = v.airline?.trim() || null
  const b = v.airline_return?.trim() || null
  if (!a && !b) return null
  if (a && b && a !== b) return `${a} / ${b}`
  return a ?? b
}
```

**표시 규칙**
| 상황 | 표시 |
|------|------|
| 항공사 없음 | 표시 안 함 |
| 항공(편도)만 있음 | `KE` |
| 왕복 동일 | `KE` |
| 왕복 다름 | `KE / OZ` |

**UI 구조 변경**
```tsx
// Before
<span className="flex-1 truncate">{voyageTitle(v)}</span>

// After
<span className="flex-1 min-w-0">
  <span className="block truncate">{voyageTitle(v)}</span>
  {airlineLabel(v) && (
    <span className="block text-xs text-slate-400 font-normal">{airlineLabel(v)}</span>
  )}
</span>
```

### 2. 항차 상세 기항지 편집 — 루트 불러오기 (`src/components/voyages/ItineraryCard.tsx`)

**배경**  
새 행사 등록(`ItineraryEditor.tsx`)에는 기항지 프리셋 불러오기 기능이 있었지만, 항차 상세의 기항지 편집(`ItineraryCard.tsx`)에는 없었음. 기존 행사 수정 시에도 동일한 편의성이 필요.

**추가된 기능**
- 편집 모드 헤더에 **루트 불러오기** 드롭다운 버튼 추가
- 드롭다운에서 프리셋 선택 시 기존 기항지가 있으면 충돌 다이얼로그 표시
  - `기존 삭제 후 불러오기` (replace)
  - `기존 유지하고 추가` (append)
- 루트 관리 버튼 → `ItineraryPresetManager` 모달 열기
- 프리셋 적용 시 `departureDate` 기준으로 날짜 자동 계산

**핵심 구현 — functional state update로 stale closure 방지**
```typescript
function applyPreset(preset: ItineraryPreset, mode: 'replace' | 'append') {
  setDraft(prev => {
    const visibleCount = prev.filter(r => !r._deleted).length
    const baseOffset = mode === 'append' ? visibleCount : 0
    const newRows: DraftDay[] = preset.ports.map((p, i) => ({
      _key: newKey(), _isNew: true, _deleted: false, id: '',
      date: departureDate ? addDays(departureDate, baseOffset + i) : '',
      port: p.port, arrival_time: p.arrival_time, departure_time: p.departure_time,
      summary: p.summary, category: '', cost: '', cost_currency: 'USD',
      sort_order: baseOffset + i + 1,
    }))
    if (mode === 'replace') {
      const markedDeleted = prev
        .map(r => r._isNew ? null : { ...r, _deleted: true })
        .filter((r): r is DraftDay => r !== null)
      return [...markedDeleted, ...newRows]
    }
    return [...prev, ...newRows]
  })
}
```

- append 시 `visibleCount`를 `setDraft(prev => ...)` 내부에서 계산 → stale closure 문제 없음
- replace 시 기존 DB 행은 `_deleted: true` 마킹(저장 시 삭제), 신규(`_isNew`) 행은 제거

### 3. 페이지 전환 시 스크롤 위치 초기화 (`src/components/Layout.tsx`)

**문제**  
페이지 라우팅(화면 전환) 후 이전 페이지의 스크롤 위치가 유지됨. 기존에 `ScrollToTop.tsx`에서 `window.scrollTo(0, 0)`을 호출했으나 효과 없음.

**원인 분석**  
실제 스크롤 컨테이너가 `window`가 아닌 `<main className="flex-1 overflow-y-auto">` 요소였음. `window` 레벨에는 스크롤이 없어서 `window.scrollTo`가 무의미.

**해결**  
`Layout.tsx`에서 `<main>` 요소에 `ref`를 부착하고, 라우트 변경 시 해당 요소의 스크롤을 리셋.

```typescript
const mainRef = useRef<HTMLElement>(null)
const { pathname, search } = useLocation()

useEffect(() => {
  mainRef.current?.scrollTo(0, 0)
}, [pathname, search])

// JSX
<main ref={mainRef} className="flex-1 overflow-y-auto">
```

## 기술 포인트

### `overflow-y-auto` 컨테이너와 `window` 스크롤 구분
레이아웃이 `h-dvh overflow-hidden` + 내부 `overflow-y-auto`인 경우, 페이지 스크롤은 `window`가 아닌 해당 컨테이너 DOM 요소에 발생한다. `window.scrollTo`는 이 구조에서 아무 효과가 없고, `element.scrollTo(0, 0)`으로 직접 리셋해야 한다.

### functional state update로 append 오프셋 계산
`setDraft(prev => ...)` 패턴을 사용하면 최신 state를 콜백 인자로 받으므로, 클로저가 stale해질 걱정 없이 `prev.filter(...).length` 같은 파생값을 정확하게 계산할 수 있다.

### 항공사 표시 — null/empty 안전 처리
`airline`/`airline_return` 모두 `string | null`이고 빈 문자열("")로 저장될 수도 있어 `?.trim() || null` 패턴으로 두 케이스를 함께 처리.
