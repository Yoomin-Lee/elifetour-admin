### 1. 배경 및 목적

기존에는 여행 행사별 협력업체 정보(랜드사 연락처, 크루즈사 담당자 등)를 별도 문서나 메모로 각자 관리.  
업체 정보 공유 및 재사용이 어렵고, 퇴사·이직 시 정보가 유실되는 문제 해소를 위해 중앙화된 협력업체 마스터 DB 구축.

- 영수증 업로드 기능은 필요 없다는 판단에 따라 계획에서 제거.

---

### 2. DB 설계

#### `partners` 테이블

```sql
CREATE TABLE IF NOT EXISTS partners (
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  type          text        NOT NULL CHECK (type IN ('LAND','CRUISE','AIRLINE','HOTEL','BUS','GUIDE','OTHER')),
  name          text        NOT NULL,
  country       text,
  region        text,
  contact_name  text,
  contact_email text,
  contact_phone text,
  website       text,
  memo          text,
  is_active     boolean     NOT NULL DEFAULT true,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
```

- 협력업체 유형: 랜드사(LAND) / 크루즈사(CRUISE) / 항공사(AIRLINE) / 호텔(HOTEL) / 버스(BUS) / 가이드(GUIDE) / 기타(OTHER)
- `is_active`: 현재 거래 중인 업체 여부 (거래 종료 후에도 기록 보존)

#### 인덱스

```sql
CREATE INDEX IF NOT EXISTS idx_partners_type      ON partners (type);
CREATE INDEX IF NOT EXISTS idx_partners_is_active ON partners (is_active);
```

#### RLS 정책

| 작업 | 권한 |
|------|------|
| SELECT | authenticated (전 직원 조회 가능) |
| INSERT / UPDATE | admin, staff |
| DELETE | admin만 가능 |

### 5. Partners 페이지 (`src/pages/Partners.tsx`)

#### 탭

| 탭 | 설명 |
|----|------|
| 전체 | 모든 업체 (건수 표시) |
| 랜드사 / 크루즈사 / 항공사 / 호텔 / 버스 / 가이드 / 기타 | 유형별 필터, 탭마다 건수 뱃지 |

#### 검색

업체명 · 국가 · 지역 · 담당자명으로 실시간 클라이언트 사이드 필터.

#### 테이블 컬럼

유형 뱃지 / 업체명(웹사이트 링크) / 국가·지역 / 담당자 / 연락처 / 이메일 / 메모 / 활성 토글 / 편집·삭제 버튼

반응형: sm 미만에서 국가/지역 숨김, md 미만에서 담당자/연락처 숨김, lg 미만에서 이메일/메모 숨김.

#### 등록·수정 모달

- 유형 선택(드롭다운) + 업체명(필수)
- 국가 / 도시·지역
- 담당자 / 연락처
- 이메일 / 웹사이트
- 메모 (textarea 3행)
- 활성 여부 체크박스

#### 활성 토글

`ToggleRight`(초록) / `ToggleLeft`(회색) 아이콘으로 즉시 토글.  
비활성 업체는 행 전체 opacity-50 처리로 시각적으로 구분.

#### 삭제

별도 확인 모달 — "되돌릴 수 없습니다" 경고 후 삭제.
