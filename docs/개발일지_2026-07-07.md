### 1. 보유현황 항공 좌석 — 항공사별 한 줄 표시 → source_flight_id 기준으로 재수정

#### 1차: 항공사 코드로 그룹핑

`InventoryTab.tsx`의 "항공 좌석" 표에서 왕복 편명(예: SQ707/SQ608)이 각 구간마다 따로 행으로 보이던 것을, 편명 앞 항공사 코드가 같으면 한 줄로 묶어 보여주도록 변경. 좌석·운임은 항공사당 한 번만 존재한다고 가정해 대표(첫 구간) 값만 표시. 조회·편집 모드 모두 적용.

#### 버그 발견: 그룹석/인디비석처럼 편명은 같은데 블록이 다른 경우

실제 행사(260612 동부지중해)에서 같은 편명이 중복 표시되는 문제 제보. 원인은 편명 앞 항공사 코드만으로 묶다 보니, 같은 편명을 그룹석/인디비석처럼 서로 다른 좌석·운임 블록으로 나눠 입력한 경우까지 하나로 합쳐버려 **편명이 겹쳐 보이고 한쪽 블록의 좌석 수가 화면에서 사라지는** 문제였음.

```ts
// 수정 전: 편명 앞 알파벳(항공사 코드) 기준
const code = flightNum.match(/^[A-Za-z]+/)?.[0] ?? flightNum

// 수정 후: 항차상세의 원본 항공편(source_flight_id) 기준
function groupFlightSegments<T extends { id: string; source_flight_id?: string | null }>(flights: T[]): T[][] {
  const map = new Map<string, T[]>()
  flights.forEach(f => {
    const key = f.source_flight_id ?? f.id
    if (!map.has(key)) map.set(key, [])
    map.get(key)!.push(f)
  })
  return Array.from(map.values())
}
```

같은 원본 항공편(왕복 구간)은 그대로 한 줄로 합쳐지고, 그룹석/인디비석처럼 서로 다른 블록은 분리되어 각자의 좌석 수가 보이도록 수정. 보유현황 목록의 "보유좌석" 합계와 메인 테이블의 항공사 뱃지 그룹핑도 같은 함수로 통일.

### 2. 보유현황 항공 좌석 — '항공' 마스터 탭 직접 입력분 제외

#### 데이터 연결 재감사

"보유현황이 항차상세 데이터를 그대로 옮겨오는지" 재확인 요청에 따라 조사한 결과, VoyageMaster의 **"항공" 탭**(`FlightsTab.tsx`, 항차상세와 별개로 전체 항공편을 직접 관리하는 마스터 화면)이 `flights` 테이블을 거치지 않고 `voyage_flights`(보유현황이 읽는 미러 테이블)에 **직접** 추가·수정하는 구조임을 확인. 이렇게 만들어진 행은 `source_flight_id`가 없고, 재동기화(`resyncVoyageFlights`)는 `source_flight_id`가 있는 행만 지우고 다시 채우도록 되어 있어(의도적 안전장치) 이런 행은 **영구 보존**되며 항차상세와 영원히 어긋난 좌석 수·항공료를 만들어낼 수 있었음.

```ts
const flightMap = useMemo(() => {
  const map: Record<string, VoyageFlight[]> = {}
  allFlights.forEach(f => {
    // '항공' 탭에서 flights와 무관하게 직접 추가한 행은 보유현황에서 제외
    if (!f.source_flight_id) return
    if (!map[f.voyage_id]) map[f.voyage_id] = []
    map[f.voyage_id].push(f)
  })
  return map
}, [allFlights])
```

보유현황은 이제 `source_flight_id`가 있는(즉 항차상세 `flights`에서 미러링된) 행만 반영하도록 필터링.

### 3. 항공편 'N편' 이름 커스텀 지정 + 좌석 등급별(그룹/인디비/비즈니스) 요금 입력

#### 배경

항차상세·새행사등록의 항공 편집에서, 여러 항공편 블록을 구분할 때 "1편", "2편" 같은 자동 라벨만 있어 실무자가 알아보기 어렵다는 요청. 또한 항공료가 그룹석 하나로 합쳐 입력되고 있었는데, 실제로는 그룹석/인디비석/비즈니스석마다 운임+유류할증료+발권피 구성이 다르다는 요청.

#### DB 마이그레이션 (`supabase/migrations/20260706000000_flights_label_and_tier_fares.sql`)

```sql
ALTER TABLE flights
  ADD COLUMN IF NOT EXISTS label              TEXT,
  ADD COLUMN IF NOT EXISTS fare_base_indivi    INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_fuel_indivi    INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_tax_indivi     INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_base_business  INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_fuel_business  INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS fare_tax_business   INTEGER NOT NULL DEFAULT 0;
```

기존 `fare_base`/`fare_fuel`/`fare_tax`는 그룹석 요금으로 그대로 유지(디폴트), 인디비·비즈니스는 새 컬럼. `label`은 비어있으면 기존처럼 "N편"으로 자동 표시.

이 마이그레이션은 Supabase CLI 토큰 권한 문제(401 Unauthorized)로 직접 적용하지 못해, 사용자가 Supabase 대시보드 SQL Editor에서 직접 실행함 (완료 확인).

#### UI 변경 (`FlightsCard.tsx`, `FlightsEditor.tsx`)

- 각 항공편 블록 상단의 "N편" 텍스트를 인풋으로 교체 — 비워두면 자동 라벨, 입력하면 커스텀 이름 표시.
- 항공료 입력을 그룹석/인디비 석/비즈니스 석 3개 소블록으로 분리, 각각 운임+유류할증료+발권피=소계.
- `voyages.ts`의 `mirrorFlightsToVoyageFlights`에서 세 등급 요금을 합산해 `voyage_flights`에 반영 — 보유현황의 항공료 합계가 항차상세와 항상 일치하도록 유지.

#### 후속 다듬기 (실무자 피드백 반영)

1. **인디비/비즈니스 요금은 필요할 때만**: "웬만하면 그룹석만 쓰고 예외적으로만 인디비/비즈니스를 쓴다"는 실무 패턴에 맞춰, 그룹석은 항상 보이고 인디비·비즈니스는 "요금 추가" 버튼을 눌러야 입력창이 나타나도록 변경(이미 값이 있으면 자동으로 펼침).
2. **편명·날짜·시각 상세 기본 1개**: 새 항공편을 추가하면 빈 목록+구간 추가 버튼 대신, 바로 입력 가능한 구간 1개가 기본으로 펼쳐진 채 시작.
3. **항공편이 없는 행사도 편집 시 기본 행 제공**: 항공편이 하나도 없는 행사를 편집 모드로 열면 "행 추가" 클릭 없이 바로 기본 행 1개로 시작(`FlightsCard.tsx`).
4. **'항공료 합계' 제거**: 좌석 등급별 소계만 있으면 충분하다는 피드백으로 전체 합산 표시 제거(편집·조회 화면 모두, `FlightsCard.tsx`/`FlightsEditor.tsx`).
5. **좌석별 요금 행 줄바꿈 방지 + 글씨 크기**: 카드 크기는 그대로 두고, 라벨을 위 줄로 분리·축약("유류할증료"→"유류할증")하고 `flex-nowrap` + 숨김 가로스크롤(`overflow-x-auto scrollbar-none`)로 압축해 카드 폭이 좁아도 줄바꿈되지 않게 함. 이후 너무 작아 보인다는 피드백으로 14px(text-sm)로 복원했다가, 본문 전체폭 사용(9번 항목)으로 여유가 생긴 뒤 다시 16px(text-base)로 키움 — nowrap+스크롤 안전장치 덕분에 글씨를 키워도 줄바꿈은 구조적으로 발생하지 않음.

### 4. 항차 마스터 탭 숨김/편집 기능

#### 1차: 5개 탭 토글 숨김

크루즈·항공·호텔·취소료·지상 5개 탭을 기본적으로 숨기고, 탭 바에 화살표 토글 버튼으로 한 번에 펼치는 기능 추가.

#### 2차: 개별 편집 방식으로 전환

"토글 방식 말고 개별적으로 숨김 가능했으면" 요청에 따라, 탭 바 오른쪽 "탭 편집" 버튼을 눌러 체크박스로 탭을 하나씩 켜고 끄는 방식으로 변경. 대상도 5개 고정 목록에서 **전체 탭**으로 확장(다른 탭은 웬만하면 숨기지 않겠지만 기능은 열어둠).

#### 3차: 앱 공통 Popover 패턴으로 재구성

"UI가 사이트 이미지와 안 어울린다"는 피드백으로, 직접 만든 div+checkbox 팝업 대신 `VoyageCombobox.tsx` 등에서 쓰던 `Popover`/`Button`/`Check` 아이콘 조합으로 교체.

숨김은 순수 UI 노출 토글이라, 탭 자체(라우팅·컴포넌트)와 DB 데이터는 전혀 건드리지 않아 다른 화면과의 동기화에는 영향 없음.

사이드바 폭을 줄이고, 토글 버튼으로 아이콘만 남기고 접을 수 있는 기능 추가. 접힌 상태에서 아이콘에 마우스를 올리면 Radix Tooltip으로 메뉴명 표시(`@radix-ui/react-tooltip` 신규 의존성 추가, 기존 `popover.tsx`와 동일한 패턴으로 `ui/tooltip.tsx` 작성).

#### 기본 접힘 + 호버 오버레이 펼침으로 재설계

"메뉴 클릭으로 이동하면 자동으로 접히고, 접힌 상태에서 호버하면 오버레이로 잠깐 펼쳐졌으면" 요청에 따라 전면 재설계:

- 메뉴 클릭 시(고정 상태가 아닌 한) 자동으로 아이콘만 남는 접힘 상태로 복귀.
- 접힌 상태에서 호버 250ms 후 펼쳐지고(스쳐 지나가는 호버로 거슬리지 않도록 딜레이), 마우스가 벗어나면 즉시 다시 접힘.
- 펼쳐질 때는 본문 레이아웃 폭을 밀지 않는 **오버레이**(absolute, 그림자)로 뜸 — 바깥 `<aside>`는 항상 고정 폭(w-20)을 유지해 레이아웃에 반영되는 폭은 변하지 않고, 안쪽 레이어만 `position:absolute`로 겹쳐서 확장.
- 기존 "접기" 버튼은 "고정(pinned)" 토글로 의미가 바뀜 — 누르면 호버와 무관하게 항상 펼쳐진 채로 고정(레이아웃 폭도 그만큼 확보).

```tsx
const expanded = pinned || hovering
// 바깥 <aside>: 레이아웃이 실제로 차지하는 폭 — pinned에만 반응
className={cn('lg:relative', pinned ? 'lg:w-64' : 'lg:w-20')}
// 안쪽 콘텐츠 레이어: 시각적 폭 — 호버 시 오버레이로 튀어나옴
className={cn(pinned ? 'lg:w-64' : hovering ? 'lg:absolute lg:w-64 lg:shadow-2xl' : 'lg:w-20')}
```

#### 접힘 아이콘이 흰 네모로 보이는 버그

접힘 상태의 로고 아이콘(`logo.png`, 1056×1024 고화질)이 흰색 네모로만 보인다는 제보. PNG를 직접 디코딩해 확인한 결과, `logo.png`는 **알파 채널은 있지만 전체가 불투명(alpha=255)** 이고 배경이 흰색이었음 — 여기 걸어둔 `brightness-0 invert` 필터가 배경과 아이콘을 구분 없이 전부 검정→흰색으로 뒤집어버려 통짜 흰 사각형이 된 것. 대안으로 검토한 두 파일(사용자가 참조한 "이라이프투어 logo.png"는 기존 `logo-full.png`와 완전 동일한 워드마크였고, 축소 아이콘 "사본 -이라이프투어 logo.png"는 배경 불투명 + 저해상도)도 모두 부적합해, 배경색이 사이드바 네이비(`#0F2849`)와 **정확히 일치**하는 `favicon.png`로 교체하고 필터를 제거해 자연스럽게 녹아들도록 수정.

### 8. 항차 검색 / 결제 스케줄 — 테이블·그리드 컬럼 너비 조정

#### 항차 검색 테이블

`table-fixed`로 전환하고 컬럼마다 내용 기준 너비를 지정. 행사명 컬럼만 너비를 지정하지 않아 남는 공간을 전부 흡수하도록 함(테이블이 억지로 넓어지는 대신 필요한 컬럼에 공간이 몰림). 크루즈 컬럼은 "WORLD EUROPA" 같은 선박명이 줄바꿈되지 않도록 넓힘. 상태/고객 컬럼은 존재하지 않는 Tailwind 클래스(`w-18`)로 인해 실제로는 폭 지정이 전혀 안 되고 있던 버그도 함께 발견해 수정.

#### 결제 스케줄 그리드

- 테이블에 `w-max` 추가 — `table-auto` 레이아웃이 컨테이너 폭을 억지로 채우던 동작 제거. 컬럼(에이전트)이 적으면 필요한 만큼만 차지하고 오른쪽은 빈 공간으로 남으며, 컬럼이 많아지거나 메모가 길어 내용이 넓어지면 기존처럼 `overflow-x-auto`로 가로 스크롤.
- 각 데이터 셀은 `w-[200px]` 고정 대신 `min-w-[200px] max-w-[260px]`로 범위 지정. 카드 자체에도 `max-w-[240px]`를 둬서 메모가 아무리 길어도 카드가 한도 없이 넓어지지 않게 하고, 메모 영역만 자체적으로 가로 스크롤(`overflow-x-auto scrollbar-none`)되도록 함(편집 모드의 `AutoTextarea`도 동일하게 감쌈).
- 왼쪽 행 이름 컬럼(총 금액, 1차 데포짓 등)에 `sticky left-0 z-10 bg-slate-50`을 적용해 가로 스크롤 중에도 고정되도록 함(결제·환불 테이블 모두).
