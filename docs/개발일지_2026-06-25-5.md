## 변경 사항

### 1. DB 스키마 변경 (`supabase/migrations/20260625000002_payment_refund_card.sql`)

**배경**  
환불 카드의 `payment_type`으로 `REFUND_1`, `REFUND_2` 등을 사용하려 했으나, 기존 CHECK 제약이 `DEPOSIT_*` 및 고정값만 허용해 INSERT 오류 발생.

**변경 내용**
```sql
ALTER TABLE payment_schedules
  DROP CONSTRAINT IF EXISTS payment_schedules_payment_type_check;

ALTER TABLE payment_schedules
  ADD CONSTRAINT payment_schedules_payment_type_check CHECK (
    payment_type IN ('DEPOSIT_1ST', 'DEPOSIT_2ND', 'BALANCE')
    OR payment_type ~ '^DEPOSIT_[0-9]+$'
    OR payment_type ~ '^REFUND_[0-9]+$'
  );
```

- `REFUND_[0-9]+` 패턴 추가로 환불 카드 타입 허용

```typescript
// REFUND 섹션: 카테고리별 카드 수 계산
const newRefundCounts: Record<PaymentCategory, number> = { ... }
for (const c of CATEGORIES) {
  const nums = schedules
    .filter(s => s.section === 'REFUND' && s.category === c)
    .filter(pt => /^REFUND_(\d+)$/.test(pt))
    .map(pt => parseInt(...))
  newRefundCounts[c] = nums.length > 0 ? Math.max(...nums) : 0
}

// Draft 빌드: 카테고리별 REFUND_N 슬롯 생성
for (const c of CATEGORIES) {
  for (let i = 1; i <= newRefundCounts[c]; i++) {
    const key = makeDraftKey('REFUND', c, `REFUND_${i}`)
    next[key] = existing ? fromSchedule(existing) : emptyCell()
  }
}
```

#### addRefundCard 변경
```typescript
// Before: 고정 카테고리(CRUISE)에만 추가
function addRefundCard() { ... }

// After: 카테고리별 독립 추가
function addRefundCard(category: PaymentCategory) {
  const newCount = refundCardCounts[category] + 1
  const pt = `REFUND_${newCount}`
  setRefundCardCounts(prev => ({ ...prev, [category]: newCount }))
  setDrafts(prev => ({
    ...prev,
    [makeDraftKey('REFUND', category, pt)]: emptyCell(),
  }))
}
```

### 3. 환불 섹션 UI 재설계

**Before** (그리드 구조)
- 결제 섹션과 동일: 1차 데포짓 / 2차 데포짓 / 잔금 행 × 카테고리 열

**After** (카테고리 컬럼 + 자유 카드)
- 결제 섹션과 동일한 카테고리 헤더(크루즈/항공/호텔/랜드/보험) 5컬럼 표시
- 각 컬럼: 자유롭게 카드 추가 가능 (REFUND_1, REFUND_2, ...)
- 각 컬럼 하단 "추가" 버튼 → 해당 카테고리에만 카드 생성
- 카드 내 날짜 레이블: **'마감일' → '환불일'**
- 카드 표시: `환불 YYYY-MM-DD` 형식


## 기술 포인트

### 카테고리별 독립 카운트 관리
`refundCardCounts: Record<PaymentCategory, number>`로 카테고리별 카드 수를 독립 관리. 기존 단일 `refundCardCount`는 전체 카드 수만 추적해 카테고리 구분이 불가능했음.

### DraftKey 재활용
기존 `${section}_${category}_${payment_type}` 형식 그대로 활용.  
환불 카드의 경우 `REFUND_CRUISE_REFUND_1`, `REFUND_FLIGHT_REFUND_2` 등으로 카테고리와 인덱스를 동시에 인코딩.  
upsertMut의 키 파싱 (`[secPart, catPart, ...rest] = key.split('_')`) 로직 변경 없이 동작.

### UNIQUE 제약 활용
DB의 `(voyage_id, category, payment_type, section)` UNIQUE 제약 덕분에 카테고리가 다르면 동일한 `payment_type`(예: `REFUND_1`)을 가진 레코드가 충돌 없이 공존 가능.
