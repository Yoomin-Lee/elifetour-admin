### 2. Google OAuth 로그인 구현

**문제 1 — Supabase Site URL 오류 (`ERR_CONNECTION_REFUSED`)**
- Supabase 프로젝트의 Site URL이 `localhost:3000`으로 설정되어 있어 OAuth 리다이렉트 실패
- Supabase Management API로 `https://yoomin-lee.github.io/elifetour-admin`으로 수정

**문제 2 — 트리거 함수 `search_path` 누락**
- `eli_handle_new_user` 트리거가 새 사용자 가입 시 `eli_profiles`를 찾지 못해 `Database error saving new user` 발생
- 원인: `SECURITY DEFINER` 함수에 `SET search_path = public` 누락
- 수정 후 트리거 정상 작동

**문제 3 — Implicit Flow vs PKCE 혼용**
- Supabase가 `#access_token=...` (Implicit flow) 형태로 토큰을 반환하는 상황 발생
- `AuthCallback.jsx`는 `?code=xxx` (PKCE) 파라미터만 처리 → "인증 코드 없음" 오류
- **해결**: `AuthCallback`에서 두 가지 흐름 모두 처리
  - `?code=` 존재 시: `exchangeCodeForSession(code)`
  - `#access_token=` 존재 시: `setSession({ access_token, refresh_token })`

**GitHub Pages SPA 지원**
- 미지원 경로 접속 시 GitHub Pages가 `404.html`을 서빙
- `404.html`에서 현재 경로를 `sessionStorage`에 저장 후 `index.html`로 리다이렉트
- `index.html`에서 `sessionStorage` 경로를 `history.replaceState`로 복원

### 3. MVP 기능 개발

#### 여행 일정 관리 (`eli_trips`)
- **목록**: 카드 그리드, 상태 필터(예정/진행중/완료/취소), 제목 검색
- **등록/수정**: 제목·목적지·출발일·귀국일·최대인원·1인요금·담당자·메모
- **삭제**: 여행자 명단 cascade 삭제 포함
- **상태 뱃지**: 색상 구분 (예정=파랑, 진행중=초록, 완료=회색, 취소=빨강)

#### 여행자 명단 관리 (`eli_passengers`)
- **목록**: 여행별 탑승자 CRUD, 이름·연락처·여권번호로 검색
- **필드**: 성명·생년월일·성별·연락처·여권번호·여권만료일·국적·객실타입·결제상태·입금액·특이사항·메모
- **CSV 내보내기**: 선사 제출용 한국어 헤더 포함, BOM(`﻿`) 추가로 엑셀 한글 깨짐 방지
- **반응형**: 데스크탑(테이블) / 모바일(카드) 이중 레이아웃

#### 대시보드
- 전체 여행 건수, 진행 중 여행, 전체 여행자 수 집계 카드
- 최근 여행 5건 목록

### 4. 역할 기반 접근 제어 (RBAC)

**역할 구분**

| 역할 | 설명 | 권한 |
|------|------|------|
| `admin` (관리자) | 시스템 전체 관리자 | 전체 CRUD + 직원 역할 변경 + 삭제 |
| `staff` (직원) | 일반 직원 | 여행·여행자 읽기/쓰기 |
| `escort` (인솔자) | 외부 현장 인솔자 | 읽기 전용 |

**Supabase RLS 정책**

```sql
-- 역할 조회 헬퍼 (SECURITY DEFINER로 RLS 재귀 방지)
create function eli_get_my_role() returns text
  language sql security definer stable set search_path = public
  as $$ select coalesce(role, 'staff') from eli_profiles where id = auth.uid() $$;

-- eli_trips: escort는 읽기만
create policy "staff insert trips" on eli_trips
  for insert with check (eli_get_my_role() in ('admin', 'staff'));

-- 삭제는 admin만
create policy "admin delete trips" on eli_trips
  for delete using (eli_get_my_role() = 'admin');
```

**트리거 보안**  
`eli_guard_role_change` 트리거로 관리자가 아닌 사용자가 자신의 `role`을 직접 변경하는 것을 DB 레벨에서 차단.

**프론트엔드 적용**
- `AuthContext`에 `profile`, `role`, `isAdmin`, `isEscort`, `canWrite` 노출
- `RoleRoute` 컴포넌트: 허용 역할 외 접근 시 `/` 리다이렉트
- 사이드바: `isAdmin`일 때만 "직원 관리" 메뉴 표시
- TopBar: 역할 뱃지 (관리자=파랑, 직원=회색, 인솔자=초록)
- 인솔자(`escort`): 등록·수정·삭제 버튼 비표시

**직원 관리 페이지 (`/users`)**  
관리자 전용. 전체 프로필 목록 조회 및 드롭다운으로 역할 즉시 변경.

### 1. 항차검색/행사 통합 조회 시스템 — 기획 및 아키텍처 확정

**배경**  
기존에 구글 스프레드시트로 관리하던 크루즈 행사 "항차검색/행사 통합 조회" 시트를
웹 애플리케이션으로 전환하는 신규 기능 개발 착수.

**요구사항 문서화**  
`docs/requirements.md` 작성. 주요 내용:

| 항목 | 내용 |
|------|------|
| 대상 사용자 | 사내 직원 전원 (조회·편집 가능) |
| 핵심 UX | 상단 행사 선택 → 개요/항공/기항지/취소료/히스토리 5개 섹션 한 화면 표시 |
| 신규 테이블 | `voyages`, `flights`, `itinerary_days`, `cancellation_policies`, `history_logs`, `audit_logs` |
| 편집 방식 | 섹션별 편집 버튼 → Dialog / 인라인 editable table |
| 실시간 동기화 | Supabase Realtime (last-write-wins + 변경 toast) |
| URL 공유 | `?voyage={id}` 쿼리 파라미터로 특정 행사 링크 공유 |

**기술 스택 검토 및 확정**

Next.js(App Router) 전환 vs 기존 Vite 유지 검토:

| 검토 항목 | Next.js | Vite 유지 |
|-----------|---------|-----------|
| GitHub Pages 배포 | `output: export` 시 SSR·API Routes 불가 | 현재 운영 중 |
| 사내 도구 SEO | 불필요 | 불필요 |
| 마이그레이션 비용 | 전체 라우팅·인증 재작성 | 없음 |
| Shadcn UI 지원 | 완벽 지원 | 완벽 지원 (공식 Vite 가이드 있음) |

**결론: 기존 Vite + React 19 스택 유지**, Shadcn UI를 신규 기능에만 추가.

**확정된 아키텍처 결정 사항**

1. **언어**: 기존 `.jsx` 파일은 건드리지 않고, 신규 파일은 모두 `.ts` / `.tsx`
2. **UI 라이브러리**: Shadcn UI + CSS 변수 — 신규 페이지에만 적용, 기존 스타일 영향 없음
3. **데이터 페칭**: TanStack Query (서버 상태 캐싱, 낙관적 업데이트)
4. **폼/검증**: React Hook Form + Zod (클라이언트·서버 공용 스키마)
5. **배포**: GitHub Pages 유지 (변경 없음)
6. **확장 방식**: 기존 앱에 페이지 추가 방식 — 전체 리빌드 없음

**Next.js 명시 기능 → Vite 환경 대체 매핑**

| requirements 원본 | Vite 환경 대체 |
|---|---|
| Server Components | TanStack Query (서버 상태 캐싱) |
| Server Actions | Supabase JS 클라이언트 mutations |
| `@supabase/ssr` | `@supabase/supabase-js` (기존 그대로) |
| Next.js middleware | React Router `<ProtectedRoute>` |
| App Router 파일 기반 라우팅 | React Router 7 (기존 그대로) |
