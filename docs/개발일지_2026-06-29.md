### 2. 결제 탭 총 금액 행 추가

#### 배경

항목별(크루즈/항공/호텔/랜드/보험) 총 결제 예정 금액을 별도 행으로 관리하는 기능 필요.

#### DB 변경

**마이그레이션 1 (`20260629000000_payment_total_row.sql`)**
- `payment_schedules.due_date` — NOT NULL 제약 제거 (TOTAL 행은 기한 없음)
- `payment_type` CHECK 확장: `TOTAL` 추가

**마이그레이션 2 (`20260629000001_payment_category_all.sql`)**
- `category` CHECK 확장: 기존 `CRUISE/FLIGHT/HOTEL` → `CRUISE/FLIGHT/HOTEL/LAND/INSURANCE`

> Supabase Management API 토큰 만료로 두 마이그레이션 모두 대시보드 SQL Editor에서 수동 실행.

#### 구현 (`PaymentTab.tsx`)

- **총 금액 행**: 각 카테고리마다 수동 입력 전용 카드 (`payment_type='TOTAL'`, `due_date=null`)
- **잔금 자동 계산**: `잔금 = 총 금액 - Σ(DEPOSIT_*)` — 저장 없이 실시간 계산, 카드에 표시
- **메모 필드 제거**: 총 금액 행에는 금액·통화만 표시 (메모 불필요)
- **upsert 수정**: TOTAL 타입은 `due_date: null` 전송, `onError` 핸들러 추가

#### 수식 최종 정의

```
총 금액 = 수동 입력 (관리자가 직접 입력)
잔금(표시) = 총 금액 - (1차 데포짓 + 2차 데포짓 + ... )
```

> 주의: `총 금액 = N차 데포짓 + 잔금` 이 아님. 총 금액 기준으로 잔금을 역산하는 방식.

### 3. 환불 섹션 총 환불 자동 계산 행 추가

#### 배경

환불 탭에 입력된 REFUND_N 금액의 합산 표시 요청.

#### 구현 (`PaymentTab.tsx`)

```
총 환불 = Σ REFUND_1 + REFUND_2 + ... (카테고리별, 통화별 합산)
```

- 통화가 다른 경우 각 통화별로 별도 합계 표시 (예: `USD 500 / KRW 200,000`)
- 자동 계산 전용 행 — 편집 불가

### 4. 달력 탭 리디자인 — 결제 마감 전용

#### 배경

달력에서 행사(항차 출발·귀국) 표시는 불필요하고, 결제 마감 가독성이 떨어진다는 피드백.

#### 제거한 요소

| 제거 항목 | 비고 |
|-----------|------|
| `fetchVoyages` 쿼리 | 항차 데이터 조회 불필요 |
| `voyagesByDay`, `voyagesThisMonth` | 항차 날짜 맵 |
| `STATUS_STYLE`, `STATUS_DOT` | 항차 상태 색상 |
| 캘린더 셀 항차 띠 | 출발·귀국 범위 표시 |
| 하단 "이번 달 출발 행사" 패널 | 목록 제거 |
| 행사 범례 | 결제 범례만 유지 |

#### 개선한 요소

| 항목 | 변경 내용 |
|------|-----------|
| 결제 항목 표시 | `카테고리 첫 글자 + 차수 + 지역명`, 완료 시 취소선 |
| 미완료 마감 표시 | 날짜 숫자 옆 주황 점(●) |
| `MAX_PAYMENT_SHOW` | 2 → 4 (공간 확보) |
| 헤더 통계 | "결제 마감 N건 + 미완료 N건 배지" |
| 하단 패널 비율 | 1:1 → 1:3 (결제 목록이 3/4 차지) |
| `ptLabel()` 함수 추가 | `DEPOSIT_1ST` → "1차", `DEPOSIT_N` → "N차" 동적 처리 |

#### 파일 (`CalendarTab.tsx`)

- 행 수: 389 → 299 (불필요 코드 제거)
- 불필요 date-fns import 정리: `parseISO`, `isSameDay`, `isWithinInterval` 제거
