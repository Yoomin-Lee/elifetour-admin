### 3. 히스토리 작성자 이름 — profile.display_name 우선 적용

#### 배경

직원 관리에서 이름을 변경해도 히스토리 댓글에는 Google OAuth 초기 이름(`user_metadata.name`)이 그대로 표시되는 문제.

#### 원인

`VoyageSearch.tsx`의 `authorName`이 `user.user_metadata.name`을 우선 참조하고, `eli_profiles.display_name`을 무시하고 있었음.

#### 수정 (`VoyageSearch.tsx`)

```ts
// 변경 전
const authorName =
  user?.user_metadata?.name ??
  user?.user_metadata?.full_name ??
  user?.email ?? '직원'

// 변경 후
const authorName =
  profile?.display_name ??        // 직원 관리에서 설정한 이름 우선
  user?.user_metadata?.name ??
  user?.user_metadata?.full_name ??
  user?.email ?? '직원'
```

- `useAuth()`에서 `profile` 추가 구조분해

#### 기존 데이터 수정

Supabase SQL Editor에서 기존 저장된 이름 일괄 변경:

```sql
UPDATE history_logs
SET author = 'MS'
WHERE author = '늠름한쇠푸른펭귄';
```

### 5. 항차 상세 — 피드백 카드 신규 추가

#### 배경

항차별 피드백(지역·크루즈·기타)을 별도로 기록·관리할 수 있는 공간 필요.

#### DB 변경

**마이그레이션 (`20260630000000_feedback_logs.sql`)**

```sql
CREATE TABLE feedback_logs (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  voyage_id  UUID NOT NULL REFERENCES voyages(id) ON DELETE CASCADE,
  logged_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  author     TEXT,
  content    TEXT NOT NULL
);
ALTER TABLE feedback_logs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "staff feedback" ON feedback_logs FOR ALL
  USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
```

**마이그레이션 (`20260630000001_feedback_logs_tag.sql`)**

```sql
ALTER TABLE feedback_logs ADD COLUMN tag TEXT;
```

> 두 마이그레이션 모두 Supabase SQL Editor에서 수동 실행 완료.

#### 수정 파일

### 7. 피드백 크로스 캐시 동기화 — 마스터 탭 ↔ 항차 상세 양방향 연동

#### 배경

피드백 마스터 탭(`FeedbackMasterTab`)과 항차 상세 피드백 카드(`FeedbackCard`)는 각각 별도의 React Query 캐시 키를 사용:
- 마스터 탭: `['all-feedback']`
- 항차 상세: `['feedback', voyageId]`

마스터 탭에서 수정·삭제해도 항차 상세 피드백 카드에 즉시 반영되지 않는 문제.

#### 수정

**`FeedbackCard.tsx`** — 이미 완료:

```ts
const invalidateAll = () => {
  qc.invalidateQueries({ queryKey: ['feedback', voyageId] })
  qc.invalidateQueries({ queryKey: ['all-feedback'] })
}
```

- `addMutation`, `updateMutation`, `deleteMutation` 모두 `invalidateAll()` 호출

**`FeedbackMasterTab.tsx`**:

```ts
const invalidateBoth = (voyageId: string) => {
  qc.invalidateQueries({ queryKey: ['all-feedback'] })
  qc.invalidateQueries({ queryKey: ['feedback', voyageId] })
}

// updateMut — onSuccess에서 editingVoyageId로 양쪽 invalidate
const updateMut = useMutation({
  onSuccess: () => {
    setEditingId(null)
    if (editingVoyageId) invalidateBoth(editingVoyageId)
    else qc.invalidateQueries({ queryKey: ['all-feedback'] })
  },
})

// deleteMut — voyageId를 variables에 포함하여 양쪽 invalidate
const deleteMut = useMutation({
  mutationFn: ({ id }: { id: string; voyageId: string }) => deleteFeedbackLog(id),
  onSuccess: (_, variables) => invalidateBoth(variables.voyageId),
})
```

- `startEdit(r)`: `setEditingVoyageId(r.voyage_id)` 추가
- `cancelEdit()`: `setEditingVoyageId(null)` 추가
- `handleDelete(r)`: `deleteMut.mutate({ id: r.id, voyageId: r.voyage_id })` 로 변경

#### 결과

마스터 탭에서 피드백 수정·삭제 → 항차 상세 피드백 카드에도 즉시 반영.
항차 상세에서 피드백 추가·수정·삭제 → 마스터 탭에도 즉시 반영.
